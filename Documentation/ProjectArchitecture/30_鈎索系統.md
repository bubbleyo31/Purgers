## 分層

```text
PlayerGrapple
├─ 鈎索發射、命中、準備拉動、拉動、釋放
├─ 左甩／直拉／右甩判定
├─ GrappleAirborne 與釋放 Momentum
└─ 命中資料
       ↓
PlayerGrappleInteractionController
├─ 讀取 GrappleInteractionTarget 類型與能力旗標
├─ 檢查目前真正載入／訂閱的 GrappleHit Ability Runtime
└─ 分派能力互動（職業只保留在 Context，不負責選能力）
       ├─ AttackGrappleMarkAbility
       ├─ SupportGrapplePullAbility
       └─ TankGrappleGatherAbility
```

## 程式職責

| 程式 | 職責 | 主要連結 |
|---|---|---|
| `PlayerGrapple.cs` | 鈎索物理與狀態核心；處理出鉤、命中、起跳 impulse、拉動、視角側甩意圖鎖定、取消原因、落地釋放及 GrappleAirborne | KCC、Movement、State Machine、Charges、Interaction Controller |
| `PlayerGrappleCharges.cs` | 依玩家等級管理鈎索使用能量、發射／拉動消耗及升級補充；保留舊類名 | `PlayerProfession`、`ProfessionDefinition` |
| `PlayerGrappleVisual.cs` | LineRenderer、命中線與第一人稱鈎索視覺；只讀 Grapple 狀態 | `PlayerGrapple`、`PlayerLocalView` |
| `GrappleAnchor.cs` | 標示普通世界可鈎掛點 | `PlayerGrapple` |
| `GrappleInteractionTarget.cs` | 描述目標是 Player／Enemy／其他、能否被各 GrappleHit 能力作用，並連到生命狀態 | `GrappleInteractionTypes`、Focus、Health |
| `GrappleInteractionTypes.cs` | 定義目標類型、相容用互動類型、多能力 Mask 與 `GrappleInteractionContext` | Router 與 GrappleHit 能力 |
| `PlayerGrappleInteractionController.cs` | 依已載入能力訂閱與目標 Capability 路由；不再用目前職業選能力，也不負責實際拉動或上標記 | Ability Runtime、Attack／Support／Tank 命中能力 |
| `SupportGrapplePullReceiver.cs` | Enemy／Rigidbody 目標被 Support 拉取的受控階段與位移 | `SupportGrapplePullAbility`、Enemy Movement Ownership |
| `SupportGrapplePlayerPullReceiver.cs` | Player 目標被 Support 拉取；以 KCC 動態速度控制並封鎖移動 | `PlayerMovement`、`PlayerGrapple` |
| `TankGatherMovementReceiver.cs` | Tank 聚怪時 Enemy 目標的受控位移 | `TankGrappleGatherAbility`、Enemy Movement Ownership |
| `AttackGrappleMarkState.cs` | Attack 鈎索命中後的標記狀態與傷害請求修改 | `AttackGrappleMarkAbility`、Damage System |

## 核心規則

- 命中後的左／右甩依玩家相對初始命中視角的轉向幅度判定，不依單純速度判斷。
- 直拉、左甩、右甩可由 bool 組合限制；若只開右甩，所有合法拉動固定走右甩。
- 側甩方向只鎖定一次，直到鈎索釋放，不可中途左右反轉。
- 命中後先用 Jump Impulse 讓玩家離地，再進拉動，減少地面摩擦卡死。
- 玩家已在空中且成功進入會拉動自身的普通 Attached 時，會把負向 `DynamicVelocity Y` 往 `0` 回正固定量；預設每次回正 `12`，但不把速度推成正值，因此連續成功鈎索可逐次減輕下墜、不可疊加升空。Attack 標記與 Support 特殊 Tether 不套用。
- 拉動期間 WS 被封鎖；AD 或預先鎖定的側向意圖控制橫向運動。
- Q2 主動取消不額外注入一份特殊爆發速度，和一般釋放使用同一套重力衰退 Momentum。
- 拉動期間按 Aim：立即釋放並進入 GrappleAirborne。
- 落地：自動釋放鈎索。
- 「看不到命中點 0.1 秒釋放」後來已納入需求；修改相關遮擋邏輯時要核對 `PlayerGrapple` 現況。

## 擴充規則

- 新增 GrappleHit 能力：先實作 `IPlayerAbilityRuntimeModule` 並標記 `GrappleHit`，再擴充 Router 的能力事件／Mask；不要在 `PlayerGrapple` 內直接硬寫職業特例。
- Router 可以保存同一次命中的多能力 Mask；現有三個會爭奪繩索控制權的能力由 Definition 互斥群組禁止共裝。
- 額外 Player／Enemy 目標 Layer 不再由 Support 職業自動開啟，而由目前可用 Ability Definition 的 `includeAdditionalGrappleTargetMask` 決定。
- 新增可互動目標：掛 `GrappleInteractionTarget` 並指定能力旗標，Receiver 應由目標自己承擔。
- Enemy 受控位移前必須取得 `EnemyMovementOwnership`，結束或取消一定釋放。
- Player Receiver 使用 KCC；Enemy Receiver 使用其既有移動／Rigidbody 架構，兩者不可共用錯誤位移方法。

## 2026-10-02 玩家等級制鈎索使用能量

> 最後核對日期：2026-10-02（本節局部核對）
> 核對來源：`PlayerGrappleCharges`、`GrappleEnergyRules`、`PlayerGrapple`、`Player`、`GameLogic`、`LocalPlayerBattleAbilityHUD`。
> 相關文件：[玩家進度](156_Phase6-B_玩家進度權威同步.md)、[戰鬥 HUD](154_戰鬥HUD視覺配置第一版.md)、[驗證紀錄](130_回歸驗證與審查狀態.md)。

本節取代舊版依職業決定次數／逐格回充的規則。左下 `PlayerGrappleMomentumEnergy` 動能增傷完全獨立，不受此變更影響。

### 正式規則與資料流

- 使用能量上限＝`levelOneEnergy + (玩家等級 - 1) × energyPerLevel`；預設 1／2／3 級為 50／75／100 點。等級來自同 Runner 的主要 `GameLogic.TryGetPlayerExperience`，不是關卡等級或職業。
- 確認合法鈎點、正式建立出鈎前扣 1 點；無合法鈎點不會發射或扣款。至少有足額發射費且能量大於零才可出鈎。
- 普通鈎索 Attached 實際拉動玩家自己時，每個 Fusion Tick 扣 `pullEnergyPerSecond × Runner.DeltaTime`，預設每秒 1 點；直拉與側甩都計入。發射準備／繩頭飛行、收繩、跳躍、釋放後 Momentum、Support 拉其他目標的 Tether 不扣持續費。
- 自動釋放／遮擋／落地等判定先執行，已結束拉動的 Tick 不再扣持續費。能量下限為 0；耗盡只禁止下一次發射，不中斷現有拉動或 Momentum。
- 無自然回充；`RestoreChargeFromKill()` 保留空入口，職業的三個舊鈎索欄位只保留序列化，不再生效。切職業不改上限或補能量。
- 升級時立即增加上限；可補滿或只補新舊容量差額。例：10／50 升 2 級，補滿為 75／75，補差額為 35／75。跨多級一次補足總差額；同級重複同步不重複補充。
- 玩家重新生成依目前等級補滿。正式 SafeHouse／Game 轉場完成也補滿；額外載入其他場景及其他玩家晚加入不替現有玩家補能量。離線重連的等級仍沿用既有進度規則：訪客以新玩家 1 級加入，Host 依存檔等級初始化；不新增能量存檔欄位。

`GameLogic` 保有等級權威。`PlayerGrappleCharges` 保有 Networked `CurrentEnergy`／`MaximumEnergy`／`AppliedPlayerLevel`／初始化狀態；Host 在 Spawned、Player 每 Tick 取輸入前、正式升級提交後同步容量。Client Input Authority 沿用玩家 Simulation 預測發射及拉動消耗，正式結果由 Host 校正；Proxy 與 HUD 不寫能量。等級資料尚未準備時先禁止出鈎，不假設 1 級覆蓋還原進度。

保留 `PlayerGrappleCharges` 類名／檔案 GUID 與舊 `playerProfession` 序列化欄位（隱藏），不需重新掛元件。舊 `CurrentCharges`／`MaxCharges` 是向下取整的相容讀值，新 HUD 應用浮點能量。`TickRecharge()` 只保留等級同步相容入口；所有恢復進度讀值為 0。`RestoreCharge(int)` 僅保留給 State Authority 明確補充，現行沒有自動呼叫方。

### Inspector 設定與調整

位置：`Assets/Prefabs/KCC_Player.prefab` 根物件 → **Player Grapple Charges** 元件。沿用既有掛載與引用，沒有自動新增 Scene／Prefab 物件。

| Inspector 欄位 | 目前預設 | 有效範圍／單位 | 效果 |
|---|---:|---|---|
| Level One Energy | 50 | ≥ 0 點 | 1 級上限；0 代表該級無可用能量 |
| Energy Per Level | 25 | ≥ 0 點／級 | 每級增加容量；0 代表固定上限 |
| Level Up Mode | 補滿至新上限 | 補滿至新上限／只補新舊上限差額 | 控制升級補能量方式；只切模式不立刻補充 |
| Launch Energy Cost | 1 | ≥ 0 點／次 | 合法發射費；0 免發射費，但總能量為 0 仍禁止出鈎 |
| Pull Energy Per Second | 1 | ≥ 0 點／秒 | 尚未釋放的玩家拉動費；0 停用持續消耗 |
| Debug Charges | 沿用目前 Prefab 設定 | 開／關 | 初始化、升級及發射紀錄，不逐 Tick 刷屏 |

建議先保留 50／25／1／1，只切換 Level Up Mode 比較效果。在 Edit Mode 修改玩家 Prefab、儲存後重新建立 Host／Client Session，讓所有同版本玩家使用一致消耗設定。Runtime 調整上限會在 Host 下一次同步套用容量差額規則；測試模式可改 Runtime 的 Level Up Mode，但不會保存至 Prefab。

### 圓環與手動驗收順序

圓環只讀 `CurrentEnergy / MaximumEnergy`，大於 50% 藍、≤50% 黃、≤25% 紅。發射瞬間下降，拉動時連續下降；無自動恢復動畫。禁止線依 `HasCharge` 顯示，因此 0.5 點不足預設 1 點發射費時也會顯示。

1. 從 `_Menu` 建立 Host，另一程序以 Client 加入；確認兩者 1 級各 50 點，切職業不補充。
2. 發射至合法地形：先扣 1；保持直拉／側甩約 3 秒再扣約 3；放開後 Momentum、一般跳躍與原地等待不扣、不回充。Support 拉其他目標只扣發射費。
3. 以低剩餘能量測試：不足 1 點禁止下一次發射；本次拉動消耗到 0 不被強制取消。
4. 先消耗到 10／50，透過既有經驗或開發 F8 升級：補滿模式應為 75／75；另開 Session 選補差額，應為 35／75。等待及擊殺本身不直接回充（擊殺造成升級則依升級規則）。
5. 死亡重生與 SafeHouse → Game → SafeHouse，各次新玩家或正式轉場完成應補到當前等級上限。
6. Client 晚加入要看到 Host 已消耗的值；Client 圓環只對應自己。訪客重連按既有 1 級進度重新滿 50。自然出鈎物理、延遲／回滾、兩端視覺仍應分別實測。

受控雙程序探針使用 `--grapple-energy-test Host|Client <SessionName> <輸出目錄>`，僅 Editor／Development Build 可用；初始化使用獨立存檔。直接呼叫扣款 API 的測試不代表自然鈎索拉動／釋放物理已驗收。實際結果見 [130](130_回歸驗證與審查狀態.md)。
