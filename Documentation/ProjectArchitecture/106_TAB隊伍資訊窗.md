## 2. 顯示內容與固定框架

1. 顯示自己及隊友：角色頭像、玩家名稱、生命／護盾與倒地／死亡狀態、目前武器，以及目前擁有的全部技能、特殊被動與成長屬性。
2. 先以最多四人配置：四個玩家欄位等高、固定外框尺寸；人數減少仍保留空玩家位置，不縮短第四列、不重新伸縮其他列。這是本視窗版面範圍，不更改 Session 人數上限。
3. 空玩家位置保留欄位與背景，頭像及資料留空，不偽造玩家血量或武器。角色頭像暫用，正式來源沿既有 Portrait Provider。
4. 技能區保留事先配置的背景格；沒對應技能則圖示／倒數留空。示意圖四個技能格僅供排版，不是技能持有數量上限，正式槽位已核對原 Loadout，第一版配置見第 8 節。
5. 「技能」標題在技能列上方，與生命列及圖示保持明確間距；四列使用相同字級、對齊與間距。
6. 不在左下角顯示「TAB 按住查看／可於設定改為切換」說明；此項已由使用者明確移除。

## 3. 按鍵、游標與安全屋投票

- TAB 預設按住顯示，放開關閉；可於玩家設定改為按一下開啟、再按一下關閉。
- 開啟時顯示游標，可移動，但不可轉視角、攻擊或主動施放技能；世界繼續運作。
- 開關只影響本機視窗，不要求其他玩家同時開關。沿既有輸入／控制仲裁，不新增另一套玩法輸入。
- **安全屋投票優先**：準備投票及可取消準備的出發倒數期間，TAB 只服務準備／取消準備，不開資訊窗。
- 資訊窗開著時開始投票：立即關窗；原本按住的 TAB 不算新的準備意圖，須放開後重新按下。
- 投票結束不自動重新開窗；下一次新按下才可開啟，切換模式也相同。
- 關窗時仍按住的攻擊／技能鍵須放開再按，避免輸入穿透。開窗本身不重設冷卻、不取消已生效效果，既有效果依原規則運行。
- 沿 PLAYER-SETTINGS 共用原 Ready 綁定，改名「隊伍資訊／準備切換」，不是增加另一個 TAB 鍵位；原 16 項索引與自訂鍵不變。新增 teamInfoToggle，舊 JSON 缺欄位時為 false（按住）。安全屋提示仍由同一 Ready 綁定取得；設定 → 操作新增隊伍資訊模式。ESC 可關閉資訊窗，若有安全屋投票則先沿既有取消投票流程。

## 4. 圖示、冷卻與懸停

- 直接使用專案目前 Definition 引用的技能、被動、屬性圖示與既有 UI 資產，不再生成或重新描繪已存在的圖示。保留完整圖案、辨識細節及既有屬性右上角符號。
- 介面沿平面深橄欖底、米白文字、淡金分隔線與 NotoSansTC 粗體。生命沿既有斜切整格表現，護盾淡金且接在同列，不以玩家辨識色替代生命色。
- 屬性顯示**目前持有階級**，不是獎勵卡的領取後下一階；沿 Growth Rank Background、Growth Rank Center／Size 與 PurgersRankSlab 各階適配。特殊被動不顯示羅馬階級。
- **最新冷卻樣式**：半透明徑向遮罩覆蓋整個技能格，從滿覆蓋開始，以十二點方向為起點順時針退去，歸零時移除；不能變成只在數字後方的一塊小底板。
- 剩餘秒數以白色粗體直接置中疊在技能格內，可加細深色描邊保持辨識。數字區不得另加背景或產生獨立色塊／色差；圖示與遮罩共用整格範圍。
- 置中數字取代早期「格子外上方」及「格內上方附深色小底板」方案。只在冷卻中顯示倒數；沒有冷卻的被動不顯示假的倒數。
- 技能生效中、冷卻中及條件不足不能使用須能區別，不將生效剩餘時間冒充冷卻。生效中／不可用的詳細造型未由這張冷卻示意定案。
- 滑鼠懸停有技能的圖示時顯示名稱與描述；空技能格不出提示。文案沿正式 Definition／獎勵資料，不另維護重複文案。

## 5. 被動與成長的可擴充排列

本節取代早期固定十五格（九屬性＋六被動）的方案；**目前內容種類數不等於未來 UI 上限**。

- 每位玩家保留固定大小的被動／成長區，按實際持有數量建立顯示項目，沒有內容時保留區域留白，不畫滿預留空圖示格。
- 一個圖示水平置中；兩個與多個圖示依數量重新排版。同行圖示間距，以及首尾圖示至區域左右邊界的留白，保持等距；同區圖示尺寸一致。
- 數量增加時可適度縮小；超過舒適顯示數量後換行，各行保持置中及一致格式，不為塞滿內容無限縮小，也不撐大外框或玩家列。
- 同一屬性升階更新原項目，不每升一階增加一格。特殊被動消耗／失去後移除並重排。
- 預覽採「屬性在前、被動在後，同類穩定順序」，用 1、2、5、8 個展示置中、縮放與換行；這是示意排列方案，**不是已定案的縮放門檻或數量上限**。
- 第一版已採用第 8 節的尺寸、換行、固定區域捲動與穩定排序；最終可讀性仍待自然操作驗收。不能把離線腳本最多示範十個的限制帶入正式玩法。

## 6. 同步與責任入口

| 資訊 | 沿用入口／責任 |
|---|---|
| 玩家名稱、身分與隊友辨識色 | GameLogic.Teammates／NetworkChatSystem；不可用名稱當穩定身分鍵 |
| 角色頭像 | PlayerPortraitProvider；目前 SharedPlayerPortraitProvider 為共用圖片，未建立個人頭像選擇系統 |
| 生命、護盾、倒地與死亡 | PlayerHealth、既有 Shield／Rescue 與 GameLogic 快照 |
| 目前武器與職業固定能力 | PlayerProfessionRuntimeManager、現行武器 Runtime／HUD Snapshot |
| 已裝技能與冷卻 | PlayerAbilityRuntimeManager、技能 Runtime、IPlayerAbilityHudState；對接已存在的權威計時 |
| 成長與特殊被動 | GameLogic.Growth／PlayerGrowthState／PlayerGrowthRules |
| 本機視窗、游標、懸停 | 本機呈現；沿現有 LocalPlayerControl、InputManager 與設定責任 |

- 所有玩家資料須同步更新，包含受傷、換裝、取得／失去技能或被動、冷卻、晚加入、重生與重連。UI 只讀權威結果，不建立平行生命、裝備或技能狀態。
- 冷卻從權威計時狀態換算，不在開窗時重新起算。只在有效 Spawned 生命週期讀 Networked 資料。
- 已沿既有 Owner 補上必要唯讀呈現介面；遠端、晚加入及重連的實際驗證範圍見獨立紀錄。
- 臨時額外施放的 Runtime 不可未經判定就當成持有技能；職業武器內建操作、裝備技能與成長被動的映射已核對，詳第 8 節。

## 9. 輸入與同步責任

- `PlayerControlMask.Combat`（16）與 Look lease 由本機 UI 持有；沿 `NetInput.BlockedControls` 傳送，Player 同樣在 Host 過濾。保留方向、Jump／Sprint／Crouch；封鎖 Fire／Aim／Reload／Q／E／F 與預留的 Ability2。資訊窗不設 SettingsMenuOpen，因此不觸發設定選單的取消鈎索路徑。
- ESC 同一幀只關閉資訊窗，不再穿透至暫停選單；獨立讀取 NetInput 的救援／自救與回血戰鬥偵測也尊重 Combat 鎖。
- InputManager 清除舊累積輸入、保留移動鍵，持續封鎖開窗期間按住的戰鬥鍵直至實際放開。既有鈎索與側閃的自然運作保留，僅禁止新側閃；不停止世界或技能 Tick。觀戰期間開窗可查看自己及隊友，但不響應切換觀戰目標。
- `PlayerActiveAbilityBase`、SupportAerial、TankAirDash 在原冷卻開始時同步本次總長度；尖刺沿既有 CooldownTicksSnapshot。Runtime 的 transfer cooldown 同時保存原分母。`IPlayerAbilityCooldownSource`／`PlayerAbilityRuntime.TryReadPresentation` 統一提供剩餘量、分母、生效與可用狀態；開窗不重算、不重啟。
- 角色死亡後 Runtime 會 Despawn。`GameLogic.Teammates` 在原死亡事件擷取八槽 `TeamAbilityDisplaySnapshot`（64 bytes，穩定 64-bit token）；僅顯示，完全不供裝備、存檔、重生邏輯讀取。Catalog token 衝突時不錯配另一技能；正式 Catalog 由測試檢查唯一性。武器沿既有 SavedProfessions 唯讀入口；成長沿原 GrowthState，消耗或倒地失去後即移除並重排。
- 新增的 Networked 欄位屬本版同步格式，連線雙端需使用相同版本；沒有增加客戶端寫入權限或 UI RPC。
