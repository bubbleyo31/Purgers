## 使用方式

新對話涉及新增、修改或打磨功能時，先用使用者用詞、同義詞、英文名與類名搜尋本檔，再沿條目讀正式規則與設定位置，最後核對現行實作和必要資產。先向使用者說明要沿用的規則，再開始設計或修改。

- 「後座力」同時命中武器射擊與 E 技能；「專注技能」可能指 E 分類或精準鎖敵。列出相關命中並依上下文區分；若仍不清楚，先詢問，不自行挑一套修改。
- 添加功能但索引與相關文件仍找不到時，先依下方「找不到功能時的必要確認」詢問是否為新功能；若否，先深入查專案文檔，再追查程式與資產。未回覆不得視為新功能。
- 正式文件的章節、程式類名及 Inspector 名稱是定位依據；索引不複製全部參數，當前值須到實際資產核對。
- 文件與程式不一致時先指出漂移；歷史規劃不應覆蓋後來已實作的行為。依 [維護規則第 1 節](120_文件維護規則.md) 核對與同步。
- 本次獲准建立索引，先收錄下列已有來源的入口；不表示重新確認原型平衡，也不表示已替技能完成資產配置或遊戲驗收。

## 找不到功能時的必要確認

適用於新對話收到「添加某功能」指令，但搜尋本索引的名稱／別名及相關模組文件後仍找不到對應規則的情況。索引不是完整功能清單；「添加」不等於「從未規劃或實作」。

1. **先詢問並等待答覆**：「目前在關鍵詞索引及相關文件中找不到這項功能。這是全新功能，還是先前已規劃／實作過的功能？」同時簡述查過的關鍵詞與文件；不要把未找到說成功能不存在。
2. **回答不是新功能**：先深入搜尋專案文檔資料，包括 Documentation/ProjectArchitecture 的模組文件、日期補充、歷史決策、設定手冊、Validation 紀錄及其他相關專案 Markdown／README。沿找到的別名、類名及資產路徑再核對 Assets/Scripts 與必要資產；找回既有規則、設定與責任入口後延續工作，不能重新發明或覆蓋原設計。
3. **深入搜尋仍找不到**：說明已查範圍，請使用者提供舊名稱、關鍵詞或原規劃位置；保持未確認，不自行假設為新功能。
4. **回答是新功能**：依既有仲裁層與資料流規劃新增；仍需確認現有責任入口是否可擴充，不能直接另建平行系統。
5. **尚未答覆**：只繼續唯讀查找或不依賴這項判定的工作，不先實作新系統；等待時間或沉默都不是肯定答覆。同一對話已明確確認新舊性質時不重複詢問。

找到遺漏的既有功能後，提出其關鍵詞、正式規則與設定位置供使用者確認是否補入索引；已獲收錄授權則直接補齊。

## RECOIL-E

**規則摘要**：E 專注能力的鏡頭與移動後座力分開設定，各自選擇觸發時機；成功施放事件經既有 PlayerAbilityRuntime 驗證生命週期、Owner、存活與 State Authority，再交給既有 PlayerMovement／KCC。不能讓 Client 或 Render 重複追加，也不套用到 GrappleHit。

- 正式規則與設定：[45 E 技能後座力配置](45_E技能後座力配置.md) 的「每個技能的修改位置」「Inspector 欄位」「網路與驗收」。
- 設定入口：各技能 Runtime Prefab 根物件 → Player Ability Runtime → E 專注能力後座力 → Recoil；沿 Ability Definition 的 Runtime Prefab 引用定位。設定不在 Definition 本身，也不需另建後座力元件。
- 實作：[PlayerAbilityRuntime](../../Assets/Scripts/Player/Ability/Loadout/PlayerAbilityRuntime.cs)、[PlayerAbilityRecoilSettings](../../Assets/Scripts/Player/Ability/Loadout/PlayerAbilityRecoilSettings.cs)。
- 規則狀態：已有正式規則；個別技能是否啟用、時機與力度須由配置決定，不自動替使用者選值。
- 實作／資產狀態：程式入口已存在；45 文件記錄十二項 E 已接入，當次資產未啟用／未設定。本輪未重讀 Prefab，不能將該歷史配置當成目前資產現值。
- 驗證狀態：最新位移驗證與限制見 [AbilityMotion V4 紀錄](Validation/AbilityMotion/README.md)，歷史鏡頭／時機證據見 [AbilityRecoil](Validation/AbilityRecoil/README.md)；V4 聚焦 47/47，完整回歸仍有既有 Boss 資產引用失敗，不能視為全套通過。
- 最後核對：2026-10-08，局部核對上述來源。
