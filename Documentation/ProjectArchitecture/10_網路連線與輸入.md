## 核心流程

```text
Unity 本機輸入
→ InputManager
→ NetInput
→ Fusion OnInput／Player Input Authority
→ Player 與各控制器在 FixedUpdateNetwork 消費
```

`NetInput` 是網路輸入快照，不應包含長期遊戲狀態。按住、按下沿與切換狀態若需要跨 Tick，應由對應 Controller 保存，例如跑步鎖定放在 `PlayerSprintLatchController`。

## 程式職責

| 程式 | 職責 | 主要連結 |
|---|---|---|
| `InputManager.cs` | 收集移動、視角、跳躍、射擊、瞄準、換彈、鈎索、蹲下／滑鏟等本機輸入，組成 `NetInput` 送入 Fusion | `NetInput`、`Player`、`PlayerMovement`、`PlayerGrapple`、`PlayerSlideController`、`AttackRifle` |
| `NetInput.cs` | 定義 Fusion 傳輸的輸入資料與 `InputButton` 按鈕位元 | 被玩家移動、武器、鈎索、職業能力讀取 |
| `Player.cs` | 取得該玩家 Tick 的 `NetInput`，協調玩家核心元件更新；也是 Player Prefab 的元件入口 | 幾乎所有 Player 子系統 |
| `GameLogic.cs` | 管理玩家加入、生成、死亡重生，並在 SafeHouse／Game 切場期間維持單一主實例、接管新場景出生設定與補回被卸載的 Player | `Player`、`PlayerHealth`、`PlayerProfession`、`ISceneLoadDone` |
| `MenuConnection.cs` | 判定 Quick Play／Host／Continue／Client Join，準備或限制本機存檔，再啟動 Fusion | `MenuConnectionBehaviour`、`GameSaveRuntimeContext` |
| `MenuConnectionBehaviour.cs` | 將 MenuConnection 接到 Fusion 連線生命週期／Behaviour | `MenuConnection` |
| `MenuSaveFlowController.cs` | Continue 選檔後重用主選單 ConnectionArgs，以 Host 身分開房 | `FusionMenuUIMain`、`JsonGameSaveRepository` |
| `MenuSaveLaunchPolicy.cs` | 以 Creating、Session 名稱與 Active Host Save 純計算連線意圖 | `MenuConnection` |
| `MenuSceneLaunchPolicy.cs` | 防止 PlayerPrefs 保留已從 MenuConfig 移除的舊 Scene，連線前解析成目前有效場景 | `MenuConnection`、`FusionMenuConfig` |
| `SafeHouseFlowController.cs` | 由 State Authority 驗證 Host 距離、處理玩家 Ready 切換、3 秒倒數並載入 Game | `SafeHouseHudController`、`GameLogic` |
| `MenuUIController.cs` | 選單 UI 操作與連線畫面控制 | Menu connection flow |

## 權威規則

- `InputManager` 只在本機採集，不直接改遠端玩家狀態。
- Player NetworkBehaviour 在 `Spawned()` 後才可讀寫 `[Networked]`。
- Client 的輸入是意圖；State Authority 才確定傷害、死亡、Enemy 生成等結果。
- Quick Play 與 Continue 的存檔只由 Host 本機寫入；Party Join 的 Client 使用 ReadOnly Context，不建立或覆蓋 Host 存檔。
- SafeHouse 的 E 只是本機請求；是否為 Host、是否在距離內、Ready 名單與切場均由 State Authority 再驗證。
- 新加入安全屋的玩家一律為未準備；離線玩家由 Ready 名單移除。Ready Check／Countdown 期間可切換自身狀態；倒數中取消會由 State Authority 立即回到 Ready Check。
- RPC 應有明確方向。Client 要求測試生成 Enemy 時，由 `EnemyPatrolAreaTestSpawner` 的 RPC 送到 State Authority，再呼叫 `Runner.Spawn`。

## 修改警戒

- 不要把新增按鍵直接散落到多個 `Update()`；能進 `NetInput` 的網路遊戲輸入應集中在 `InputManager`。
- 純本地 Debug 熱鍵可以留在測試元件，但正式 Build 要能停用。
- 不要在 `NetInput` 保存冷卻、生命或職業，這些不是輸入。

## 2026-10-17 區域路由與可恢復連線（局部核對）

最後核對日期：2026-10-17。核對來源：`MenuConnection.cs`、`MenuConnection.SessionEnd.cs`、`MenuConnectionAttempt.cs`、`MenuRegionRouting.cs`、`MenuConnectionBehaviour.cs`、`MenuSessionEndState.cs`、`Assets/Settings/MenuConfig.asset`。

### 區域與房間代碼

- 沿用原 Fusion Menu、同一個 Runner 及 8 碼代碼；不新增連線、存檔或轉場系統。
- MenuConfig 的原索引 `0=Best、1=us、2=usw、3=eu、4=sa` 保留；追加 `5=asia、6=au、7=cae、8=hk、9=in、10=jp、11=za、12=kr、13=tr、14=uae、15=ussc`。此順序是房間代碼的協定，不可任意插入、排序或刪除。中國大陸 cn 需要獨立服務設定，未直接加入一般 Cloud 清單。
- 區域代碼依 [Photon 官方區域文件](https://doc.photonengine.com/fusion/current/manual/connection-and-matchmaking/regions) 核對。清單代表設定支援，不保證當前 AppId 的 Region Allowlist 或各區網路可達。
- `RequestAvailableOnlineRegionsAsync` 沿用 SDK 介面名稱，但只立即回傳與設定完全同序的選項，**不是即時測速結果**。Best 佔位 Ping=0，固定區域為未知值；不在開啟 Party 時偷偷啟動不可取消的查詢。
- Host 指定區域時直接用該區域編碼；Best 先由同一 Runner 的 `JoinSessionLobby` 取得實際區域，允許 Photon 使用區域快取，再用此區域編碼並 `StartGame`，不另建查詢 Runner。Quick Play、Fresh Host、Continue 共用此路由。
- Client 從代碼解析固定區域，覆蓋本機偏好，不重新選 Best。舊固定區域代碼保留索引；舊 Best 代碼沒有實際區域資訊，明確提示房主更新並重開房，不猜測／掃描所有區域。新舊版本混用不保證相容。

### 取消、逾時與重試

- 每次 `ConnectAsync` 建立獨立 `MenuConnectionAttempt`，涵蓋 Best 選區、Photon 啟動及初次載入。預設 **30 秒**；`_Menu` 既有 MenuConnectionBehaviour Inspector 的「連線等待 / Connection Timeout Seconds」可調，最小 1 秒。已連線後的 Fusion 斷線判定不受此值控制。
- 按取消或到期時停止等待，不依賴底層 Task 主動完成。遲到成功／失敗只能結束舊工作，不能切換新 UI、更新新 Runner 或重新進房。
- 清理最多再等待 **5 秒**，包含尚未 IsRunning 的 Runner。逾期則隔離、銷毀本次 Runner；觀察殘留 Task 的例外。清理使用本次 callback／場景快照、釋放本次 LocalSceneTransition 控制票證，並保留原來的 Single／Multiple Peer 清理責任。
- 清理及新存檔回滾完成後才釋放連線中的互斥限制。取消直接回主選單；逾時／失敗先回主選單再使用既有 Popup 提示。原 SDK 呼叫端收到 CustomResultHandling，不得再次顯示過期畫面。
- 主動離開立即標記本次 Session 結束；連線中取消不顯示「房間已關閉」。已成功連線 Client 的非主動斷線仍沿用既有 RoomClosed 流程。
- 失敗的新 Host 存檔會回滾；Continue 保留既有檔案；Client 不建立本機存檔。Console 新增區域與階段耗時，不記錄 AppId 或玩家識別資料。

### 設定與驗收

本次透過 Unity Editor 儲存 MenuConfig，沒有重接 Scene／Prefab。設定變更需重新 Build 才會出現在舊的 Windows 執行檔；房主與加入者應使用同版。

驗收順序：設定選 asia → Host 開房 → 另一端即使選 eu 也能用代碼加入 → 重開 Best 房間確認實際區域 → 連線途中按取消 → 逾時後關閉提示 → 從主選單重試 → Host 關閉後 Client 保留原房間關閉提示。檢查沒有殘留 Runner、黑幕或 AllInput 鎖。

驗證證據與已知限制見 [ConnectionRecovery](Validation/ConnectionRecovery/README.md)。可取消期限依賴 Unity 主執行緒仍能更新；它不是作業系統或同步資源載入凍結時的強制中斷器。
