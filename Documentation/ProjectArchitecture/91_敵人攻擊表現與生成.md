## 戰鬥決策流程

```text
EnemyCombatDecisionController
→ 從已註冊的 EnemyCombatOption 評估可用性與優先級
→ 選定一個 Option
→ Telegraph / Startup / Active / Recovery
→ 完成或取消
→ 釋放 Action Gate 與 Movement Ownership
```

## 核心程式

| 程式 | 職責 |
|---|---|
| `EnemyCombatCore.cs` | 定義 Option Id、Action Phase、Tick Result、`EnemyCombatOption` 抽象基底與共用 Enemy Damage Utility |
| `EnemyCombatDecisionController.cs` | 集中挑選並驅動一個攻擊 Option；管理目標、階段、冷卻、Action Gate 與轉向控制 |
| `EnemyCombatAnimatorDriver.cs` | 將目前 Option、Phase、Chase 等狀態轉成 Animator 參數 |
| `EnemyPresentationAnimatorDriver.cs` | 綜合 Idle／Patrol／Alert／Chase／Combat 狀態驅動整體 Animator 與 MoveSpeed 平滑 |

## 攻擊實作

| 程式 | 職責 | 適用類型 |
|---|---|---|
| `EnemyMeleeSwingAttack.cs` | 典型靠近玩家後揮砍；由武器／Hit Volume 實際接觸合法玩家才送出傷害，並防止單次揮擊重複命中 | Melee A |
| `EnemyMeleeDashAttack.cs` | 直線突進；Dash 狀態中 Hit Radius 接觸即傷害，對每目標防彈跳；預測會離開 NavMesh 時提前停止，玩家離開前方 180 度持續 1.5 秒後停止 | Melee B |
| `EnemyRangedProjectileAttack.cs` | 建立並發射網路投射物 | Ranged A／可配置變體 |
| `EnemyProjectile.cs` | 投射物移動、碰撞、存活期與 DamageRequest | Ranged Projectile |
| `EnemyRangedBeamAttack.cs` | Aim 約 1 秒、鎖定後凍結射線方向、等待約 0.5 秒、以瞬間 Beam／Hitscan 出傷 | Ranged B／可配置變體 |
| `EnemyBeamPresenter.cs` | LineRenderer 表現；鎖定前以較低頻率平滑跟隨，線穿過玩家後延伸到後方／場景終點 | Beam Attack |

## 遠程攻擊轉向

Ranged A 與 Ranged B 在整個攻擊流程中取得面向控制，持續面向鎖定玩家，直到 Recovery 完成後才釋放。這個控制必須由 Combat Decision／Option 的生命週期統一收回，避免取消、死亡或受控時永久卡住轉向。

## 近戰出傷原則

- 近戰 A 不使用「敵人面前偵測到玩家，Active Delay 到了就直接扣血」。
- 劍／武器 Hit Volume 必須實際碰到玩家 Collider 才加入候選。
- Active Window 仍由 Tick 狀態決定，Animation Event 可以打開／關閉 Hit Volume，但不能單獨作為網路傷害真相。
- 同一揮擊／Dash 對同一玩家只傷害一次，下一次攻擊才清空命中集合。

## 防禦設計狀態

設計上 Ranged B 等變體可同時擁有 Defense A 與 Defense B；2026-09-15 重新核對目前 149 支程式後，仍未看到獨立 `EnemyDefenseA/B` 實作檔。不可在文件中宣稱已完成：

- Defense A：正面吸收傷害，結束後回復「吸收傷害 × 20%」，背後無防禦。
- Defense B：正面可擊破護盾（預定 150），防禦中回血，背後無防禦。

未來實作時應加入 `EnemyCombatOption` 或獨立 Defense Controller，並接上 Damage Request Modifier、Action Gate、Movement Ownership 與 Animator Driver。

## 測試生成

| 程式 | 職責 |
|---|---|
| `EnemyPatrolAreaTestSpawner.cs` | 預設 F4，從指定或 Runtime 自動規劃 Patrol Area 節點生成 Network Prefab；Client 以 RPC 要求 State Authority；支援區域輪替、占用檢查、數量上限與 Gizmos |

測試生成器只用於開發。State Authority 在 `Runner.Spawn` 的 `onBeforeSpawned` 直接把本次生成來源的 `EnemyPatrolArea` 指定給 `EnemyIdlePatrolBrain`，因此多個 Runtime Chunk 不需要依賴全場景唯一 Area Id。Phase 10 正式 Encounter 程式沿用同一個出生前綁定契約；其 Scene／Prefab 尚待配置。

## 2026-10-02 視野外短暫追蹤

`EnemyCombatOption.requiresDirectSight` 保留序列化欄位名稱，但改讀 Perception 的 `HasCombatSight`：正常視線，或曾親眼看見且仍在有限保留時間／半徑內的無遮擋視線。投射物 Startup、光束 Tracking 同步使用此判定，快速繞出扇形不再立刻取消；光束 LockedDelay 的固定世界瞄準點與命中遮擋維持原規則。Combat Context 在沒有直接視線或有效保留時只讀最後位置快照。網路寫入仍屬於 State Authority，新增狀態與 Inspector 操作見 [90](90_敵人核心感知巡邏與追逐.md)。
## 2026-10-02 生成遮擋選項

每個 `EnemySpawnZone` 新增預設勾選的「生成需要視野遮擋」。Host Director 取消此限制時，只略過出生點的全員遮擋 Raycast，仍檢查所有玩家最小距離；落後清理維持遮擋要求。無新增網路狀態或 Prefab／Scene 自動遷移。設定與驗收見 [164](164_Phase10_怪物生成區與Encounter守則.md)。

## 2026-10-02 定點光束冷卻瞄準

Combat Controller 在無 Active Option、有效即時目標及 Stationary 旋轉權成立時，選擇最高 Priority 且 `SupportsBetweenActionAiming` 的 Option，呼叫 `AimBetweenActions`。目前只有 Beam opt-in，重用其 Tracking Turn Speed／FaceTarget；原攻擊期的獨占轉向、冷卻與 BeamEndPoint 都不改。未新增元件、Networked 欄位或 Client Gameplay 寫入，仍以 NetworkTransform 同步朝向。設定及測試見 [165](165_RangedC_定點砲台與生成配置.md)。
