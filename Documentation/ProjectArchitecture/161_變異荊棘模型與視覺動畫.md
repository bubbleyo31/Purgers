## 交付與邊界

三款原創深褐色、密刺、緊湊球塊型模型，各有三層靜態 Mesh LOD，共用一份 URP Lit 材質與 1024×1024 BaseColor。未使用參考圖片作貼圖。

FBX 的 `Detail0/1/2` 對應 Prefab 的 LOD0/1/2；刻意避免 FBX 檔名使用 `_LOD1`，防止 Unity 自動辨識為缺少 LOD0 的模型群組。FBX 內部有單位換算 Transform；表格使用 Unity Renderer 世界 Bounds，不能拿原始 Mesh Bounds 當公尺尺寸。

這是**美術與本機動畫資產**：尚無 Collider、傷害、生命、NetworkObject、生成器接線或阻擋飛行的實戰行為。沒有加入目前的 Scene／MapChunk，也沒有修改原有 Prefab instance。尚未執行 Play Mode、獨立 Host/Client 或大量生成效能驗收。

## 動畫選擇與責任

採用程式驅動 `Visual` 子階層，無 Animator、骨架或 SkinnedMeshRenderer。呼吸是微幅非等比縮放，受傷是短促旋轉與壓縮；本版本不是每根藤分別蠕動的骨骼動畫。

`MutantThornVisual` 只更新視覺，每個 instance 使用不同呼吸相位，不消耗遊戲 Random 狀態。使用 `Time.time`，會隨 Time Scale 暫停。停用元件／回收物件時還原作者設定的局部位置、旋轉、縮放；再次啟用重新擷取基準。不要在啟用期間更換 Visual Root，也不要讓另一個 Animator 同時寫這個 Transform。

`PlayHitReaction(float strength = 1f)` 是未來已確認受擊事件的表現入口。強度限制在 0～1，重複呼叫重新起算；本方法不決定傷害、不發 RPC。未來仍由 Host／State Authority 提交世界結果，再由每個 Client 的表現端播放。呼吸相位不需同步，受傷事件要由未來障礙物的既有權威流程轉送。

## Inspector 設定與調整

開啟任一荊棘 Prefab，選取根物件的 `Mutant Thorn Visual`：

| 欄位 | 預設 | 有效範圍／相依 | 效果與起始調整 |
| --- | --- | --- | --- |
| Visual Root | `Visual` | 必須是自己的子階層，且不得含 Collider | 根物件與碰撞體保持不動；無效引用會停止視覺更新 |
| Breath Amplitude | 0.025 | 0～0.08，比例 | X/Z 約 ±2.5%，Y 為其 0.7 倍；細微可改 0.015，0 關閉 |
| Breath Frequency | 0.32 | 0.1～2 Hz | 週期為 1/f；預設 3.125 秒，緩慢可改 0.2 |
| Hit Duration | 0.28 | 0.05～1 秒 | 平方衰減；微抽動可用 0.18～0.28 |
| Hit Angle | 3 | 0～10 度 | X 旋轉振幅，Z 為其 0.6 倍；0 停止旋轉 |
| Hit Compression | 0.035 | 0～0.08，比例 | X/Z 與 Y 反向壓縮，乘上受擊強度與衰減 |

材質 `Thorn_DarkWalnut.mat`：Base Map 為 `Thorn_BaseColor.png`、Base Color 白色、Metallic 0、Smoothness 0.13、Enable GPU Instancing 開啟。URP 的 Metallic/Smoothness 欄位為 0～1；偏乾燥可用 Smoothness 0.05～0.15。額外的 Roughness PNG 是 DCC 來源資料，未接到 Unity Metallic Map；不能直接當 Smoothness 使用。實際色調仍受場景照明與曝光影響。

根物件 `LOD Group` 的螢幕相對高度閾值為 0.28、0.12、0.015；低於 0.015 剔除。這是相對高度，不是公尺距離。若遠處密集，先嘗試提高前兩個閾值，使低面數版本提早切換；用正式相機移動觀察刺尖輪廓跳變。沒有打開 Cross Fade，以免增加過渡期間的渲染與材質需求。

## 手動加入與 Play Mode 檢查順序

1. 在你選擇的測試 Scene 放入一個上述 Prefab，先使用根物件 Scale `(1,1,1)`，再依飛行通道寬度等比縮放。以兩三公尺球團為本版尺寸起點，不宣稱適合目前所有地圖通道。
2. 核對階層為 `Thorn_* / Visual / LOD0、LOD1、LOD2`，根物件有 `LODGroup` 與 `MutantThornVisual`，Visual Root 指向 `Visual`。
3. 進入 Play Mode，觀察約三秒一輪微呼吸；多個副本應錯開相位。模型不應整體位移或不斷累積縮放。
4. 在元件右鍵選「預覽受傷微抽動（Play Mode）」；應約 0.28 秒內回到單純呼吸，這不造成任何遊戲傷害。
5. 關閉元件，應立即回到原始姿勢；再開啟應恢復呼吸，無殘餘抽動。
6. 以正式相機遠近移動，確認 LOD 切換、深褐色在場景光線中的辨識度、飛行速度下刺尖輪廓是否清楚。
7. 未來要阻擋玩家時，在根或 `Visual` 以外的 `Collision` 同層配置簡化 Collider。不要把 Collider 放進 Visual，否則動畫會拒絕該階層。大球 Collider 會封掉刺間空隙；不能把此近似當成刺尖逐根精確碰撞。碰撞尺寸要配合 KCC 與飛行路徑實測後決定。
8. 大量生成前，先在代表性相機與密度下用 Profiler 量測 CPU、draw calls、陰影與 LOD；共用材質與 Instancing 開關不等於已經通過效能驗收。需要靜態合批的物件不能同時讓 Visual Transform 動畫。

所有設定存於 Prefab／instance，沒有寫入玩家存檔。未來多人關卡必須使用相同資產版本；模型大小、Collider 與生成位置必須服從同一套權威配置，不能由各 Client 自行抽選。
