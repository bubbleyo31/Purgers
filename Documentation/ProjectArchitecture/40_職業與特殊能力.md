# 職業與特殊能力架構

> 最後核對：2026-09-15  
> 相關文件：`30_鈎索系統.md`、`41_玩家能力Loadout.md`、`50_武器瞄準與射擊.md`、`60_傷害生命死亡與回饋.md`

## Runtime 啟用流程

```text
Player
├─ PlayerProfession（目前職業）
│  └─ PlayerProfessionRuntimeManager
│     └─ ProfessionDefinition → PlayerProfessionRuntime → Runtime Driver
│        └─ 職業武器、F 近戰／Quick Action、Tank Guard、Tank Quick Dash
└─ PlayerAbilityRuntimeManager
   └─ PlayerAbilityLoadoutDefinition
      └─ 獨立 PlayerAbilityRuntime
         └─ GrappleFocus / GrappleHit 能力模組
```

職業 Runtime 與能力 Runtime 是兩條平行生命週期。F1／F2／F3 只替換職業 Runtime；能力 Runtime 不會因此 Despawn，所以 Active 狀態與冷卻不會被切職業刷新。

> 遷移狀態：原始碼與 Editor 工具已完成，但 Definition、Ability Runtime Prefab 與預設 Loadout 必須在 Unity 執行 `Tools/Player Ability/建立初始能力 Runtime 與 Loadout` 後才會建立。尚未執行前，舊職業 Prefab 上的能力副本仍然存在，不能把「程式已支援」寫成「資產已完成搬移」。

## 共用程式

| 程式 | 職責 |
|---|---|
| `PlayerProfession.cs` | 保存／同步目前職業，串接 GameLogic 與 Runtime Manager |
| `ProfessionDefinition.cs` | ScriptableObject 職業設定，包括類型與鈎索資源等資料 |
| `PlayerProfessionRuntime.cs` | 封裝某一職業的 Runtime 元件組合 |
| `IPlayerProfessionRuntimeModule.cs` | 可直接掛在任一職業 Runtime Root 的共用 Gameplay Module 介面；由 Runtime 自動綁定與逐 Tick 驅動 |
| `PlayerProfessionRuntimeManager.cs` | 啟用唯一當前 Runtime，套用輸入 Modifier，轉交 Action Gate 來源 |
| `PlayerProfessionRuntimeDriver.cs` | 所有職業 Driver 的共用生命週期與輸入／武器入口 |
| `PlayerQuickActionController.cs` | 呼叫目前職業的 `IPlayerQuickActionAbility` |
| `IPlayerQuickActionAbility.cs` | Quick Action 統一介面 |
| `PlayerAbilityTypes.cs` | 定義 `GrappleFocus`／`GrappleHit` 分類、職業 Mask 與每能力職業規則 |
| `PlayerAbilityDefinition.cs` | 單一可裝備能力的 ID、分類、Runtime Prefab、職業限制、互斥群組與優先權 |
| `PlayerAbilitySlotLayoutDefinition.cs` | 各能力分類可開放 0～N 格，不固定一格專注加一格命中 |
| `PlayerAbilityLoadoutDefinition.cs` | 裝備清單與容量、重複、Prefab、互斥驗證 |
| `PlayerAbilityRuntime.cs` | 獨立網路能力實例；綁定 Player、保存能力狀態與冷卻 |
| `PlayerAbilityRuntimeManager.cs` | 生成／排序／驅動 Loadout Runtime；Fusion 技術上限八格，實際格數由 Layout 決定 |
| `IPlayerAbilityRuntimeModule.cs` | 可裝備能力模組統一介面；處理 Tick、Owner Binding 與職業可用性切換 |

## Attack

| 程式 | 職責 | 連結 |
|---|---|---|
| `AttackProfessionRuntimeDriver.cs` | Attack 職業啟用、輸入路由、武器與職業綁定行為組裝 | Rifle、Weapon Focus、Quick Melee |
| `AttackQuickMelee.cs` | Attack 快速近戰，使用共用傷害與回饋規則 | `IPlayerQuickActionAbility`、Damage、Feedback |
| `AttackFocusAbility.cs` | 瞄準／Focus Target 驅動的 Attack 特殊能力與結束原因 | Aim、Rifle Shot Modifier、FocusTarget |
| `AttackGrappleMarkAbility.cs` | Attack 鈎索命中後對合法目標施加標記 | Router、`AttackGrappleMarkState` |
| `AttackGrappleMarkState.cs` | 標記持續狀態，透過 Damage Request Modifier 改變傷害 | Damage System |

## Support

| 程式 | 職責 | 連結 |
|---|---|---|
| `SupportProfessionRuntimeDriver.cs` | Support 的武器與職業綁定行為組裝 | SupportSMG、Quick Melee、Healing |
| `SupportQuickMelee.cs` | Support 快速近戰 | Quick Action、Damage、Feedback |
| `SupportAerialAbility.cs` | `GrappleFocus` 可裝備能力；只在 GrappleAirborne 且 Aim 未被 Action Gate 封鎖時啟動；關閉後才開始完整 CD；壓縮原速度並封鎖 WASD | Ability Runtime、Movement Modifier、NetInput、Action Gate、State、可選 SupportSMG |
| `SupportRifleHealingAbility.cs` | 透過 `IRifleHitOverride` 把 Attack Rifle 命中隊友轉成治療 | AttackRifle、PlayerHealth、Health System |
| `SupportGrapplePullAbility.cs` | 判斷 Support 鈎索目標並啟動 Player／Enemy Receiver | Grapple Router、兩種 Pull Receiver |

`SupportAerialAbility` 不再要求目前職業必須是 Support，也不再強制依賴 `SupportSMG`。完成資產遷移後，正式載入點是獨立 `PlayerAbilityRuntime`；Attack、Tank 或 Support 只要 Loadout 裝備此 Definition 就能使用。若該 Ability Runtime 同 Root 有 `SupportSMG` 才額外連動其特殊射速、補量與彈藥規則。

冷卻採結束起算：`BeginAbility()` 只建立 Active Timer，Aim 放開、落地、離開 GrappleAirborne 或時間到都集中進 `EndAbility()`，由該處才建立完整 Cooldown Timer。能力 Active 的時間不得扣除冷卻。

## Loadout、職業限制與互斥原則

- `PlayerAbilitySlotLayoutDefinition` 可分別設定 GrappleFocus 與 GrappleHit 的 0～N 容量；不得在程式寫死槽位數。
- 每個 `PlayerAbilityDefinition` 都有獨立 `restrictProfession + allowedProfessions`。關閉限制即跨職業；開啟後切到不合法職業只暫停能力，不卸裝、不清冷卻。
- F 近戰／Quick Action、`TankQuickDashAbility`、`TankGuardAbility` 目前仍屬職業 Runtime，不納入玩家 Loadout。
- 因此 Quick Dash／Guard 目前不是「取消 Definition 上的限制就能跨職業」；未來要共用時，必須先把它們提升成獨立 Ability Runtime／Definition，再由職業規則控制。不可只加一個看似可切換、實際卻不會在其他職業 Spawn 的 bool。
- 初始遷移建立的五個 Grapple 能力皆預設不限職業。日後可直接在各自 Definition 打開職業限制，不必改能力程式。
- 現有兩個 GrappleFocus 都會接管 Aim 與移動，因此同屬 `GrappleFocusMovementAuthority` 互斥群組。
- 現有三個 GrappleHit 都會決定繩索後續，因此同屬 `GrappleHitRopeAuthority` 互斥群組；GrappleFocus 與 GrappleHit 可同時裝備。
- 多能力事件採 `executionPriority → Loadout 槽位順序 → Ability ID` 的穩定順序。
- 攻擊、防禦、瞄準、換彈、Quick Action 的互斥透過 `PlayerActionGate`，不是每兩個技能彼此互查。
- 能力修改移動使用 `IPlayerMovementInputModifier`；修改受傷使用 `IPlayerIncomingDamageModifier`。
- 動畫只是讀取能力狀態，不決定能力是否成立。
- Tick 計時使用 Fusion `TickTimer`；本地 Animator 時間不能作為伺服器傷害真相。
