# 隊友辨識、分格生命與穿牆輪廓

最後核對日期：2026-10-13（本輪局部核對）  
核對來源：GameLogic.Teammates、NetworkChatSystem、LocalTeammateHUD、LocalHealthSegmentView、LocalMinimapController、TeammateOutlineFeature。  
相關文件：[100 UI](100_UI觀戰與聊天.md)、[60 生命](60_傷害生命死亡與回饋.md)、[147 小地圖](147_PrePhase4-4_小地圖與戰爭迷霧.md)、[167 分格 HUD](167_已確認HUD美術與整格血量.md)。

## 已確認需求與本輪範圍

- 其他隊友頭頂顯示名稱與分格生命，名稱／血條穿牆；不顯示自己的頭頂 UI。安全屋與 Game 使用同一套。
- 生命為米白格，護盾為淡金格，直接接在可見生命格後方，共用同一列；整列格子（含容量底格）依實際繪製寬度置中於名稱下方。殘血時只有生命格變紅，辨識色與護盾色不變。
- 輪廓平時淡、隔牆加強，厚度／透明度／亮度可調。
- 畫面外只顯示同色方向箭頭，不附名字、距離或血條。身後方向採已預覽的畫面下緣路徑；回到名條安全範圍恢復頭頂資訊。
- Host 自動配發紅、藍、綠、黃；超過四人沿用這四種色系的亮／低彩度與暗色版本。目前對齊既有 GameLogic 容量 12 人，不增加遊戲人數限制。
- 名條、輪廓、箭頭、地圖隊友標誌共用辨識色；死亡／重生／跨關保持顏色。離開 Session 釋出色槽，不重排其他玩家；重新連線視為新 PlayerRef 配發空槽，不承諾跨 Session 身分。
- 死亡位置與名稱留在 GameLogic。畫面內顯示菱形骷髏及「已死亡」，地圖顯示同色死亡符號；畫面外仍僅箭頭。原有重生完成後清除死亡標記，不新增倒地或救援玩法。
- 已建立獨立設定／UI Prefab；2026-10-13 使用者追加「配置自動接線」後，已保存 _Menu HUD、KCC_Player 錨點與 8 個身體 Renderer，以及 Balanced／HighFidelity／Performant 三份 Renderer Feature。既有工作區修改保留。

## 資料與責任

1. `GameLogic.Teammates.cs` 為原 GameLogic partial，新增 NetworkDictionary<PlayerRef, NetworkTeammateIdentity>。只由已 Spawn 的主要 State Authority 配色、保存名稱與死亡位置；公開查詢先檢查生命週期。
2. 名稱沿用 `NetworkChatSystem` 原 RPC、來源驗證與清理；註冊成功時寫入主 GameLogic 快照。晚加入者透過 Networked 字典取得舊玩家名稱，不依賴歷史加入 RPC。未完成名稱註冊前顯示 Player 編號。
3. `LocalTeammateHUD` 每端只讀指定 Runner；自動模式只接受唯一有效本機 Runner。使用世界相機投影至 Screen Space Canvas，不做 Gameplay 遮擋／傷害判定。
4. `LocalHealthSegmentView` 新增快照入口，仍共用原整格餘額、格數、護盾起點、顏色與繪圖。每格預設 20，累積滿一格增減；低血量顏色依**精確 HP/maxHP**即時判定，預設 <=25%。資料來自 PlayerHealth 與既有 PlayerShieldAbility。
5. `LocalMinimapController` 增加同 Runner 隊友圓點／死亡標記；不受敵人的探索與視線規則限制。超出當前小地圖範圍時不繪製；不變更地形、敵人、撤離或迷霧資料。
6. `TeammateVisualAnchor` 人工指定頭頂 Transform 與第三人稱身體 Renderer；不搜尋第一人稱手、武器或特效。
7. `TeammateOutlineFeature` 在世界相機 URP Forward Renderer 的 AfterRenderingTransparents 畫輪廓，ZTest 分別控制可見／隔牆強度。只畫當前相機綁定 HUD 的目標，不畫本機角色或死亡殘影。

## 配置維護步驟（本專案已接線）

目前頭頂錨點為 `Visual/ThirdPersonModel/Head/TeammateNameAnchor`，初始 Root 高度 2.15m；身體引用沿用 PlayerLocalView 的 8 個 Model Parts。HUD 採單 Runner／Camera.main 自動綁定。以下為日後換模型、搬場景或新增 Renderer 時的維護步驟，不需再重複放置。

1. 若資產缺少，執行 **Tools > Purgers > UI > Create Teammate Display Assets**。只建立缺少的資產，不覆寫已存在的設定，也不放置場景。
2. 將 `Assets/Prefabs/UI/TeammateDisplay.prefab` 放入 `_Menu/GameplayHUD Canvas/PlayerHUDCanvas` 的既有 Screen Space Canvas 下，與 DamageNumbers 同層；RectTransform 保持拉滿、offset=0、Scale=(1,1,1)。不可放在 World Space Canvas 或裁切 Mask 中。避免在 Game／SafeHouse 再各放一份。
3. Local Teammate HUD 指定 `TeammateDisplayV1.asset`；單 Runner 可讓 Runner／World Camera 留空。若指定相機，必須是遊戲世界相機，不能是 ViewModel 相機；多 Runner 必須同時指定 Runner 與各自世界相機。
4. 開啟 `Assets/Prefabs/KCC_Player.prefab`，Root 加 `TeammateVisualAnchor`。可在第三人稱頭部之上手動建立空錨點，指定 Head Anchor；未指定時依 Root + Fallback Head Height。
5. Body Renderers 僅加入第三人稱身體 MeshRenderer／SkinnedMeshRenderer；可參考 PlayerLocalView 的 Model Parts，不能包含第一人稱手、武器、粒子或其他玩家。換模型後需重查引用。
6. 開啟目前世界相機所用的 `URP-HighFidelity-Renderer`（若品質等級使用其他 Renderer，也需對應處理），**Add Renderer Feature > Teammate Outline Feature**；Outline Shader 指定 `Assets/Shaders/Teammates/TeammateOutline.shader`，確保 Build 不被裁除。不要加到 ViewModel 專用 Renderer，不要重複加入。
7. 目前實作保留 stencil bit 128，前後只清此位元；以 URP Forward 為目標。後續加入使用相同位元的特效或改為 Deferred，須先處理遮罩衝突。輪廓 Shader 不自行啟用 Bloom。
8. 人工保存各項指定修改。兩端必須使用相同程式版本；GameLogic 新增 Networked 字典會改變網路版型。

## 人工驗收與限制

- 兩個獨立程序開 Host／Client，確認名稱與紅藍辨識色一致；加入更多玩家檢查四基色、粉／淺色及暗色。
- 對方受傷至門檻、治療越過門檻、獲得與耗盡護盾：只生命格變紅，盾緊接生命且維持淡金；重生不保留舊 UI 餘額。
- 遠近、隔牆、局部遮擋、多人重疊、背後、上／下方、高低 FOV、16:9／超寬／視口縮放：只出現對應名條或箭頭，方向不鏡像、不被邊緣裁掉。
- 實際第三人稱動畫／不同身體分件檢查輪廓接縫；法線外擴輪廓可能受硬邊、開口網格及透明材質影響。太陽光、Bloom 及模型最終外觀需實機驗收，不能用概念 GIF 代替。
- 死亡到重生間，仍看到最後死亡位置；玩家離線後移除。晚加入與切換安全屋／Game 應保持名冊一致，無上一場殘留。
- 目前本機死亡、既有相機解除綁定時，自動相機模式會隱藏隊友 HUD；未擴充觀戰相機的額外切換規則。
- 實際執行證據與未驗項目見 [驗證紀錄](Validation/Teammates/README.md)。
