# 傷害、生命、死亡與回饋架構

> 最後核對：2026-09-14  
> 相關文件：`40_職業與特殊能力.md`、`50_武器瞄準與射擊.md`、`91_敵人攻擊表現與生成.md`

## 共用傷害管線

```text
攻擊來源
→ 建立 DamageRequest
→ DamageReceiverUtility 尋找 IDamageReceiver
→ Request Modifier
→ PlayerHealth 或 TestDamageReceiver
→ DamageResult
→ 攻擊來源提供 ICombatDamageFeedbackSource
→ PlayerCombatFeedbackRelay
→ HitMarker / CameraShake / Feedback Audio
```

## 傷害協定

| 程式 | 職責 |
|---|---|
| `DamageSystem.cs` | 定義 `DamageType`、Hit Zone、強制暴頭來源、拒絕原因、`DamageRequest`、`DamageResult`、`IDamageReceiver`、`IDamageRequestModifier` 與 Receiver 查找工具 |
| `WeaponHitZone.cs` | 將碰撞部位對應到 Damage Hit Zone |
| `MeleeDamageResolver.cs` | 共用近戰候選查詢、去重、陣營／生命過濾、送出 DamageRequest 並彙總結果 |
| `ContinuousDamageZone.cs` | 由 State Authority 定時傷害區域內玩家；清除已離線／Despawn 玩家引用 | 
| `ICombatLifeState.cs` | 提供統一的存活／死亡查詢，讓互動與命中不依賴某一種 Health 類別 |
| `ICombatDamageFeedbackSource.cs` | 讓武器或技能把權威 DamageResult 送至玩家回饋層 |
| `CombatFeedbackId.cs` | 定義一般命中、暴頭、擊殺等回饋類型 |

## 生命與死亡

| 程式 | 職責 |
|---|---|
| `HealthSystem.cs` | 定義 Heal／Revive Request、Result、拒絕原因，以及生命改變、死亡、復活事件與 `IHealthReceiver` |
| `PlayerHealth.cs` | 玩家權威生命、受傷、死亡、傷害來源快照與事件；連到 GameLogic 重生 |
| `TestDamageReceiver.cs` | Enemy 目前正式使用的生命／治療／復活／死亡事件 Receiver；名稱仍是歷史遺留 |
| `CombatDeathHandler.cs` | 共用死亡時停用碰撞、Focus、生命狀態與相關表現／遊戲物件控制 |
| `EnemyDeathLifecycleController.cs` | Enemy 死亡階段、延遲消失與未來死亡擴充介面 |
| `EnemyDefinition.cs` | Phase 6-C 的基礎擊殺經驗配置；不在傷害管線內計算獎勵 |
| `GameLogic.cs` | 玩家死亡後等待 3 秒，從 Inspector Spawn Point 陣列重生並恢復原職業 |
| `LocalPlayerSpectatorController.cs` | 玩家死亡 1 秒後切到其他玩家觀戰，重生時退出 |

Phase 6-C 局部補充：`TestDamageReceiver.Died` 中的最後一筆 `DamageResult` 是擊殺者來源；`EnemyDeathLifecycleController` 只在 State Authority 的首次正式致死且關卡 Active 時交給主要 `GameLogic`。環境死亡和缺乏可靠致死資料的補救流程不發經驗；詳見 [157](157_Phase6-C_敵人擊殺經驗發放.md)。

## 玩家傷害 Modifier

```text
DamageRequest
→ PlayerIncomingDamageModifierBridge
→ 目前啟用的 IPlayerIncomingDamageModifier
→ 例如 TankGuardAbility
→ 修改或拒絕 Request
→ PlayerHealth 套用結果
```

傷害來源不應直接查找 Tank Guard，否則未來護盾、護甲或 Buff 會形成多條不一致路徑。

## 回饋層

| 程式 | 職責 |
|---|---|
| `PlayerCombatFeedbackRelay.cs` | 將權威 DamageResult 整理成攻擊者本機的 `CombatHitFeedbackData`，必要時透過 RPC 回到 Input Authority |
| `PlayerHitFeedbackController.cs` | 本機訂閱 Relay，分派 Hit Marker、Camera Shake 與其他第一人稱回饋 |
| `FirstPersonHitMarker.cs` | 顯示命中、暴頭或擊殺 UI |
| `FirstPersonHitCameraShake.cs` | 依回饋類型驅動第一人稱相機震動 |
| `FirstPersonDamageFeedbackAudio.cs` | 播放命中、暴頭、擊殺回饋音；優先序為擊殺 > 暴頭 > 一般命中 |

Tank 普攻第三段與 GrappleAirborne 特殊攻擊能以 `DamageForcedHeadshotSource` 標示為暴頭回饋；這是回饋／規則資料，不代表一定要命中頭部 Collider。

## 不可破壞條件

- 先得到 `DamageResult` 再播放命中回饋，不能射線碰到東西就先播普通命中。
- 同一擊殺只播最高優先回饋，不能同時播命中、暴頭、擊殺三個聲音。
- Receiver 對失效 NetworkObject、已死亡目標與重複命中必須拒絕。
- Enemy 生命尚未從 `TestDamageReceiver` 正式遷移前，不得新增另一套 EnemyHealth 平行運作。

## 2026-09-17 局部核對與架構補充

MeleeDamageResolver 在任何提前返回前先清空 resolvedResults／confirmedResults，無效查詢不會重用上一刀擊殺結果。DamageReceiverUtility 先確認 Receiver，再執行來源 IOutgoingDamageModifier、目標 IDamageRequestModifier 及 Receiver；補齊 Result 後通知來源 IOutgoingDamageResultListener 一次。FullyBlocked 也通知一次；NoReceiver 不執行 Modifier／通知。此通知不取代 PlayerCombatFeedbackRelay。來源倍率只修改 RequestedDamage，保留 BaseDamage。
