# 聲音系統架構

> 最後核對：2026-09-14  
> 相關文件：`50_武器瞄準與射擊.md`、`60_傷害生命死亡與回饋.md`、`70_第一人稱模型與動畫.md`

## 兩條播放路徑

```text
本地第一人稱聲音
事件來源 → GameplayAudioService → FirstPerson Mixer Group

世界可聽聲音
State Authority／武器事件
→ NetworkPlayerAudioEmitter
→ 各 Client 的 GameplayAudioService
→ World Mixer Group，跟隨發聲 NetworkObject
```

## 程式職責

| 程式 | 職責 |
|---|---|
| `GameplayAudioCue.cs` | 單一音效 Cue 設定，包含 Clip、音量、音高、播放方式與 Network Delivery 類型 |
| `GameplayAudioCatalog.cs` | 集中保存可重用 Cue，提供武器、傷害與移動系統引用 |
| `GameplayAudioService.cs` | 本機音效播放中心；管理一次性、跟隨型 One Shot 與持續 Loop |
| `NetworkPlayerAudioEmitter.cs` | 將世界聲音透過網路送到所有玩家，並以發聲者 NetworkObject 作為跟隨座標 |
| `FirstPersonAnimationAudioEvents.cs` | Animator Event 播放本地換彈、拉槍機、武器機械細節音 |
| `FirstPersonMovementAudioController.cs` | 本地走路、跑步、跳躍、落地、滑鏟、鈎索／飛行風聲與 Loop 狀態 |
| `FirstPersonDamageFeedbackAudio.cs` | 本地命中、暴頭、擊殺回饋音與優先序 |

## Audio Mixer 建議樹

```text
MainAudioMixer
└─ SFX
   ├─ FirstPerson
   └─ World
```

- `Local First Person Fallback Group` 指到 `MainAudioMixer/SFX/FirstPerson`。
- `World SFX Fallback Group` 指到 `MainAudioMixer/SFX/World`。
- Fallback 是 Cue 未指定 Mixer Group 時的預設輸出，不是新的 Audio Mixer 資產。

## 路徑判斷

| 聲音 | 路徑 |
|---|---|
| 換彈拉槍機、第一人稱手部細節 | Local First Person |
| 本地走路、跑步、滑鏟、風聲 | Local First Person |
| 命中／暴頭／擊殺提示 | 攻擊者 Local First Person |
| Attack／Support 槍聲 | Network World，且跟隨射手 |
| Tank 普攻三段揮擊聲 | Network World，音檔播放期間跟隨 Player Audio Origin |
| Tank 特殊攻擊世界聲 | Network World |
| Enemy 攻擊聲 | Network World |

槍聲 One Shot 不能留在開槍瞬間的固定世界座標。射手移動時，聲源在生命期內必須跟隨射手；`GameplayAudioService` 的 Following One Shot 與 `NetworkPlayerAudioEmitter` 負責此行為。

2026-10-20 局部核對：電鋸 `TankMeleeCombo` 的 Light1／Light2／Heavy 共用 `PlayFollowingWorldOneShotFromStateAuthority`，各端由既有 `GameplayAudioService.LateUpdate` 更新聲源至該 Player 的 Audio Origin（未指定時為 Player Root），直到音檔結束。仍在正式 Gameplay Active 時由 State Authority 發聲，揮空也播；Cue、音量及傷害時序不變，不新增 RPC 或序列化設定。Player 銷毀後沿用既有 OneShot 行為，在最後有效位置播完尾音。特殊攻擊撞擊聲維持原入口。

本次驗證：Unity 重新編譯後檢查實際載入的 `TryPlayWorldSwing`，呼叫已由固定位置切換為 Following 入口；Console 未見編譯錯誤。`TankPreparationTests`、`TankPreparedDashTests`、`WorldAudioLoopTests` 聚焦共 19／19 通過（MCP job `ee0b15c7e7834a21a612c74aac54c245`）。完整 `PurgersRegression` 兩次均在進度 34 項、`AbilitySlotCenteringTests.DifferentAspectRatiosStayCenteredInTheSlot` 附近遇 Domain Reload 並失去結束結果，已清理失效 job；不能視為回歸通過。未執行 Host／Client 實際移動聽感、獨立程序或 Build 驗證。

## 擴充規則

- 新增聲音先建立／指定 `GameplayAudioCue`，不要讓每支能力自行建立 AudioSource 池。
- 需要所有人聽見才經過 Network Emitter；不要廣播第一人稱細節音。
- 持續聲音必須有明確 Start、Update 跟隨與 Stop／Despawn 清理路徑。
- 只根據權威 DamageResult 播命中回饋，並維持擊殺 > 暴頭 > 命中。

## 2026-10-17 鈎索世界循環聲（局部核對）

最後核對日期：2026-10-17。核對來源：GameplayAudioService.WorldLoops、NetworkPlayerAudioEmitter、PlayerGrapple.Feedback。

GameplayAudioService 新增 StartWorldLoop／HasWorldLoop／FadeOutWorldLoop／StopWorldLoop，與本機 Loop 分開持有 handle，使用共用 ConfigureSource 與 World Mixer fallback。世界 Loop 來源可重用，上限預設 32，滿載拒絕新聲音而不搶占；LateUpdate 跟隨目標，目標銷毀或停用時清理，服務停用／銷毀停止全部世界 Loop。呼叫者也必須在玩法狀態結束、停用、Despawn 時釋放自己的 handle，不能停止其他玩家的聲音。FadeOutWorldLoop 由當前音量線性淡出，使用 unscaledDeltaTime；重複呼叫不重設計時。淡出期間仍占用原 handle／voice，結束才回收；StopWorldLoop 可立即切斷尾音，重用聲源會重設音量。

NetworkPlayerAudioEmitter.StartFollowingWorldLoop 驗證既有 Catalog，沿用 defaultWorldAudioOrigin。Loop 的持續條件由同步玩法狀態提供，不使用容易遺失或晚加入漏接的 Start/Stop RPC。鈎索 Host 選定變體／Pitch 並同步，各端重建同一設定；發射／命中一次聲仍走原 State Authority RPC。沒有每 Tick 音效 RPC。Host 正式射出時同步遞增序號，各端因此切掉前次拉動尾音；一般停止拉動使用 PlayerGrapple 的 0.15 秒淡出設定。

三個 Cue、音檔、Inspector 與完整時機見 [30](30_鈎索系統.md#2026-10-17-鈎索世界音效與成功出鈎震動)，實際配置與驗證見 [紀錄](Validation/GrappleFeedback/README.md)。原 FirstPersonMovementAudioController 的本機鈎索／慣性風聲不改。

## 2026-10-18 全滅轉場音量（局部核對）

核對來源：GameplayAudioTransitionGain、PlayerSettingsMenu.Runtime.ApplyAudio、LocalSceneTransition.Wipe。沿用 MainAudioMixer 的 `PlayerMasterVolume`；使用者的 master 偏好先轉成原本 dB，再加上轉場線性增益的 20 log10 值（零增益為 -80 dB）。不改偏好資料、不改 Cue／AudioSource 播放責任，不使用 AudioListener.volume。

每個 LocalSceneTransition 持有自己的增益 owner，多 owner 取最小值；Release 只移除自身，取消或恢復完成後回到當前使用者音量。PlayerSettingsMenu 每幀套用設定時同樣經此合成入口，不會把黑幕靜音蓋回去。正式音訊應經既有 Mixer 路由；繞過 Mixer 的外掛聲源不在本合成範圍。時間與生命週期見 [144](144_PrePhase4-1_共用控制與轉場.md)，驗證見 [紀錄](Validation/SpectatorSwitch/README.md)。

## 2026-10-18 雷射階段音效接口（局部核對）

三個雷射從既有同步權威階段與序號在各端驅動 Prepare／Aim／Charge／Fire；不重複廣播另一份音效 RPC。固定 Cue Clip Index／Pitch 保證設定一致，Cue 可用 ID 0，既有 NetworkPlayerAudioEmitter 路徑不變。準備／發射沿 GameplayAudioService.PlayWorldOneShotFollowingTransform，細線／中線可使用既有 StartWorldLoop／StopWorldLoop。新增 StartWorldLoopWithVolume 接受呼叫端音量；原 StartWorldLoop 四參數介面不變，以音量 1 轉呼叫，保留一般與反射呼叫相容性。第一次快照不補舊一次聲，但可恢復持續階段循環；取消、換段、停用、Despawn 釋放自身 handle。接口已接、音檔未填；操作與限制見 [108](108_雷射四階段視聽呈現.md)。
