# 武器獎勵與換裝

最後核對日期：2026-10-10（局部核對）。
核對來源：GameLogic、PlayerRewardDefinition／Catalog／SaveBridge、PlayerProfessionRuntimeManager、PlayerQuickActionController、TankQuickDashAbility、BulletTracerLineDrawer、LocalPlayerRewardHUD，以及本次使用者定案。

## 已確認玩法

- Attack 步槍、Tank 電鋸、Support SMG 與 Q／E 共用升級獎勵池。保留十四份既有技能，新增三份武器，合計十七份。
- 三把最低等級 1、權重 1、Repeatable；排除目前武器，換掉後可再次抽到。不保證每次候選包含武器。
- 選到後立即替換目前武器，不建立背包／武器庫；成功才消耗一份待選獎勵。
- 保留整套現有操作，包括 Tank 連段、格擋、F 衝刺與 Support 一般隊友治療。不新增已擱置的 Support 無限彈匣、特殊射速等效果。
- 換裝槍械滿彈匣，使用新 Runtime 原有初始化備彈；電鋸回待機。舊開火、瞄準、換彈、連段、格擋及 F 動作退出。
- Q／E 保持相同 Runtime、裝備、作用狀態與冷卻；受到武器資格限制者仍遵守原規則。精準鎖敵在近戰時結束作用並封鎖使用，但不卸除，不因換回槍械刷新冷卻。
- 換裝不額外補血／盾，也不清空一般移動速度。Tank 正在衝刺時經原 ForceCancelDash 結束該衝刺的運動，不延續舊武器的強制位移。
- F 每把獨立記錄，離手期間依 Fusion 模擬時間繼續倒數。Attack／Support 現行沒有額外獨立 Cooldown 欄位：保留尚未完成的 Startup／Active／Recovery 到可再用 F 的剩餘時間，不憑空新增冷卻數值。Tank 額外保留充能格數、逐格回充進度及衝刺後僵直；離手跨越多個回充間隔時逐格補回，最多到容量。
- 死亡重生、正常換關、讀檔保留武器種類；整輪失敗重設為 Attack。死亡／換場的其他資源初始化沿用原規則，本次 F 保存保證針對同一 Player 生命週期內的武器替換，不新增離線冷卻或 F 存檔。
- Host 保存自己的裝備；訪客只保留本次 Session。真正斷線重連後的訪客沿用既有新加入政策，不新增帳號持久化。

## 權威與責任

`GameLogic` 的現有抽池／版號／RPC 來源驗證保持。候選建立與領取前都排除目前武器。領取分流：
- 能力：既有 `TryEquipRewardAbilityStateAuthority`。
- 武器：`PlayerProfessionRuntimeManager.TryEquipRewardWeaponStateAuthority`，沿用唯一當前 Profession Runtime、既有 Driver／武器／F／格擋；不生成第二套武器管理器。

新 Runtime Spawn 成功後，才收尾舊 F／武器、還原新武器 F 保存狀態、提交職業與 Runtime 引用、Despawn 舊 Runtime。失敗保留原武器、候選及待選數；重複或過期領取不生效。只允許 State Authority 提交正式結果，HUD 只讀。

Manager 新增容量三的 `QuickActionReserves` NetworkDictionary；`PlayerQuickActionController` 新增容量三的 `UnequippedRecovery` NetworkDictionary。Tank 快照為 `WeaponQuickActionReserve`，使用同一 Runner 的模擬時間計算；不使用電腦時鐘。

## 保存與相容

沿用 `SavedProfessions` 保存當局武器種類；獎勵換裝成功立即更新。Host 寫檔時取正式當前武器，經 `PlayerRewardSaveSnapshot.EquippedWeaponId` 寫入已有的 `GameSaveData.EquippedWeaponId` 欄位，存檔版本維持 v3。
穩定武器 ID 固定為 `weapon.attack`、`weapon.tank`、`weapon.support`，不把可配置的獎勵卡 ID 當作武器類別。讀檔在第一次 Player Spawn 前填入 SavedProfessions；空白／未知 ID 回退 Attack。新加入不再把剛讀入的武器清除。失敗重設更新當局保存及活玩家職業，避免死亡收尾再次保存舊武器。

## 清理邊界

- `BulletTracerLineDrawer` 追蹤本身生成的 GameObject。ClearTracers 停止協程，立即隱藏並銷毀各 Tracer，包括場景根或外部 Tracer Root 下的物件；正常飛行結束也移出清單。
- Manager 換裝與各端 `PlayerProfessionRuntime.Despawned` 清除本 Runtime 的 Tracer、AudioSource 與粒子；元件停用／銷毀亦有後備清理。
- 原 `PlayerAimController.Despawned` 移除自身 FOV request；原武器網路狀態隨 Runtime 消失。舊 ViewModel 先解除武器引用並停用，再銷毀，觸發槍口火焰與動畫／音效元件收尾。
- 只處理舊武器擁有的內容，不全場搜尋刪除同名物件，不清除其他玩家或獨立 Q／E 投射物／效果。玩家根部既有命中火花／彈孔仍由原 FIFO／生命期管理，不把已完成命中回滾。
- 場景、玩家 Prefab 與武器 Runtime Prefab 不需新增接線；人工調校維持原樣。

## Inspector 調整

正式池：[PlayerRewardCatalog](../../Assets/Resources/Progression/PlayerRewardCatalog.asset)。Game／SafeHouse 未設覆蓋時讀這份 Resources。
三份資產位於 `Assets/_Project_Assets/Data/Progression/Reward_WeaponAttack.asset`、`Reward_WeaponTank.asset`、`Reward_WeaponSupport.asset`。

| 欄位 | 目前值／規則 |
|---|---|
| Stable Reward Id | weapon.attack／weapon.tank／weapon.support；已被候選／存檔引用後不要任意改名 |
| Category | Weapon |
| Minimum Player Level | 1，範圍 ≥1；只影響新候選 |
| Weight | 1，範圍 ≥0；0 停止新抽，不刪除舊候選／保存查找 |
| Repeat Policy | Repeatable；目前裝備仍排除 |
| Ability Definition | Weapon 必須留空 |
| Weapon Profession | 對應 Attack／Tank／Support，None 無效 |
| Weapon Display Name／Icon | 獎勵卡名稱與既有三張武器 Sprite；不變更武器美術 |
| Description | 既有卡片排版內的短說明 |

新增武器卡不可只增加 enum；目前只支援以上三套既有操作。未來擴充須同步 Runtime 路由、穩定保存 ID、裝備排除、F 狀態及驗證。

## 驗收順序

1. 建立隔離新存檔，確認 Attack；升級候選不出現目前武器，選 Tank／Support 後圖示、武器、操作與滿彈匣一致。
2. 在開火／Tracer 尚存／換彈／ADS／F／Tank 格擋或衝刺中換裝，檢查舊效果、FOV、控制鎖、音效與 HUD 清理；其他玩家及 Q／E 效果不受影響。
3. 使用 F 後換走再換回，確認各武器剩餘冷卻；Tank 測未滿一格與跨多格時間。Q／E Runtime、冷卻及護盾等狀態維持。
4. 精準鎖敵作用時換 Tank，確認作用終止、技能仍裝備但不可用；換回槍械不刷新冷卻。
5. 死亡重生、Game／SafeHouse 往返、Host 存檔重開、整輪失敗；依前述表現驗證。
6. 獨立 Host／Client 分別領取，測過期／重複請求、失敗不扣獎勵、晚加入與訪客重連。Single Runner 不取代獨立多人或最終視覺驗收。
