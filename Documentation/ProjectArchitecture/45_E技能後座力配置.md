## 本次狀態

十二項 E 專注能力都已提供兩組獨立可配置後座力，包含十項新 E、空中緩速、空中衝刺。**本輪沒有保存 Scene／Prefab／Definition，也沒有覆寫人工配置。** 未配置欄位的程式預設停用、時機為「未設定（不觸發）」；這不代表目前所有資產仍停用。V3 最終唯讀檢查：榴彈與衝擊扇波兩通道開啟／Timing=2；貫穿砲鏡頭開啟／Timing=2；精準鎖敵鏡頭開啟／Timing=3。閃現仍停用／Timing=0。Camera Timing 與 Movement Timing 現在各自支援複選；原有 0／1／2 數值相容，3 為兩者皆選。

設定放在各顆 Runtime Prefab 根物件既有的 **Player Ability Runtime → E 專注能力後座力 → Recoil**。不需新增元件、不改 KCC_Player，也不在 Ability Definition 設定；Definition 的 Runtime Prefab 引用可用來定位正確資產。

## Inspector 欄位

下表為程式初始值，人工配置後可不同；這次沒有序列化寫回這些資產。V4 新增 Movement Decay Duration：舊資產未配置時載入 0.2 秒，因此已啟用移動後座力的手感會改變，需要以新公式人工校準；既有速度、方向與時機值保持。

| 欄位 | 初始值 | 範圍、單位與效果 |
|---|---|---|
| Camera Enabled | 關閉 | 鏡頭後座力獨立開關；開啟後仍需選時機 |
| Camera Timing | 未設定 | 複選「開始準備／前搖開始前」與「實際施放／前搖結束後」；閃現對應第一次 E 與第二次成功 E，兩項全勾各觸發一次 |
| Camera Angles | (0, 0) | 每個觸發事件的總角度，度；X = Pitch，負數抬頭、正數低頭；Y 絕對值為左右交替幅度，第一次向左、第二次向右，0 關閉。Pitch 受 KCC 限制 |
| Camera Application Duration | 0.06 | >= 0 秒；分段施加時間，0 立即施加，總角度不變 |
| Camera Recovery Delay | 0.1 | >= 0 秒；從最後觸發起算，且待施加角度結清後才回正 |
| Camera Recovery Speed | 20 | >= 0.1 度／秒；向上 Pitch 的回正速度，不超過剩餘可回正角度 |
| Movement Enabled | 關閉 | 玩家移動後座力獨立開關 |
| Movement Timing | 未設定 | 相同兩項複選時機，與鏡頭獨立；兩項全勾時，各按觸發當下方向追加一次速度 |
| Movement Speed | 0 | >= 0 公尺／秒，後座力初速；負值視為無效果。搭配衰減時間決定額外距離 |
| Movement Decay Duration | 0.2 | >= 0.01 秒；線性降速至零。單次無阻擋額外距離 = Movement Speed × 秒數 ÷ 2 |
| Movement Local Direction | (0, 0, -1) | 觸發時的瞄準座標，X 右、Y 上、Z 前；可正可負，會正規化。零向量回退為視線反向 |

兩組效果都需要「Enabled 開啟＋有效 Timing＋非零數值」才看得到。只調角度或速度、沒選時機，仍然不觸發。

鏡頭後座力沿用槍械的 WeaponRecoilApplication.Step，屬於真正的 KCC 瞄準角度增量，不是本機 Camera Shake。每個成功事件先把角度加入待施加池，每 Tick 分段取出；同一技能再次觸發會合併尚未施加角度並重新起算施加時間及回正延遲。

回正沿用槍械規則：只處理已實際施加且尚未手動抵銷的向上 Pitch；Yaw 與向下 Pitch 不自動回正。自動回正必須同時滿足「待施加角度結清」及「最後觸發的回正延遲到期」，每 Tick 最多恢復 Camera Recovery Speed × Runner.DeltaTime。KCC 在極限角度截掉的未施加部分不計入回正池。

**槍械與技能同時作用**：PlayerMovement 在每 Tick 實際套用玩家 LookDelta 後，記錄真正的向下角度額度。技能依既有 Loadout 穩定順序先消耗，之後槍械只消耗剩餘量；1 度輸入最多抵銷合計 1 度後座力。系統施加／自動回正不增加額度，不會被另一來源當成手動壓槍。這是原 PlayerMovement 的 Tick 內暫存，Fusion 重模擬會重新從當次輸入建立；不保存跨 Tick 額度。

AttackRifle／SupportSMG 的施加時間、回正延遲、速度及射擊數值維持原值；回正改用同一個 WeaponRecoilRecovery 純規則與共用輸入額度。舊 LastAimPitch 網路欄位保留，但不再用相機角度差推算玩家輸入。詳見 [50 槍械](50_武器瞄準與射擊.md)。

移動公式（V4）：

`初速向量 = Quaternion.Euler(觸發 Pitch, 觸發 Yaw, 0) × normalized(方向) × Movement Speed`

`本次額外距離 = 初速向量 × Movement Decay Duration ÷ 2`

在該時間內線性降速至零，以每 Tick 的曲線區間積分取出位移，交給原 PlayerMovement → PlayerSlideController → KCC ExternalDelta。後座力不混入 DynamicVelocity，地面與空中摩擦不再改變這部分距離；一般走路、原速度與重力保留。碰牆／地板仍受 KCC 碰撞解算，被擋掉的當 Tick 位移直接消耗，不能累積至之後補發。向上後座力期間只抑制 GroundSnap，避免貼地吸回；不關閉碰撞。

重觸發將新距離加入尚未消耗的向量並重新起算衰減時間；兩個時機各自取觸發視角，總距離不因重設時間放大。方向相反可互相抵銷。沒有碰撞／其他移動仲裁／減速時，10 m/s × 0.4 s ÷ 2 = 2 m；5 m/s × 0.2 s ÷ 2 = 0.5 m。

預設方向仍是真正三維視線反向：看下方往後上推，看上方往後下推；向量長度不放大力道。保證的是技能提供的額外位移，不是整段世界軌跡：玩家本身移動、下落、斜坡及地板阻擋仍可能改變最後位置。

## 觸發規則與特例

- 一般新 E：冷卻、存活、裝備、使用條件、輸入鎖與 Action Gate 均放行後，才觸發 BeforeCast；前搖到期且技能回報成功施放才觸發 AfterCast。單純按鍵被拒絕不觸發。
- 有前搖時：AfterCast 的方向取正式施放當下視角，不沿用最初按鍵方向。先取本次攻擊起點／準星並執行技能，再加入鏡頭偏移；同一事件的移動方向也取鏡頭後座力之前的視角。
- Cast Delay Seconds = 0：兩個階段同一 Tick 順序發生，每個通道在每個勾選階段各觸發一次；全勾就是同 Tick 兩次。施加時間為 0 時立即施加兩次，非零時合併進待施加池。即時 BeforeCast 偏移會影響隨後瞄準；AfterCast 不會踢偏剛射出的攻擊。
- 在前搖結束前死亡、卸下 Runtime、職業／武器資格失效而中止，AfterCast 不會補發。已發生的 BeforeCast 後座力不撤銷。資格失效或輸入被鎖時，已受理的後座力仍可完成施加／回正；死亡清除待施加與回正池，Runtime 卸下不把狀態帶到新技能。
- AfterCast 是「成功提交正式效果」事件，不要求命中敵人。起點阻擋而取消發射、投射物無法建立、子彈時間超過名單容量等失敗，不發 AfterCast；已發生的 BeforeCast 不撤銷。
- **閃現**：第一次 E 成功進入 Armed 只發 BeforeCast（開始準備）；第二次 E 通過限制並正式進入 Dashing 才發 AfterCast（實際施放）。單選後者時第一次 E 完全不踢鏡頭；全勾時兩個階段各一次。長按、拒絕衝刺及待命到期均不發 AfterCast；衝刺方向先取樣，再套用鏡頭後座力。
- **空中緩速／空中衝刺**：依使用者確認，任一或兩個 Timing 勾選，均合併為成功啟動瞬間一次。拒絕啟動不觸發；空中衝刺貼近敵人直接執行 Arrival Attack 的合法消耗也會觸發。
- 空中緩速仍按 Active Velocity Multiplier 壓縮本次後座力位移，衰減時間正常消耗；後座力不再存入 StoredDynamicVelocity，也不在緩速解除時返還。原有玩家動量的保存／返還不改。子彈時間也仍縮放當 Tick 位移，因此相同衰減時間內的實際距離會縮短。
- 閃現、Tank 空中衝刺、普通鉤索附著拉動與外部拉玩家期間，後座力時間照常消耗，但該 Tick 額外位移被高優先權移動覆蓋，不在結束後補發；失效期限避免 KCC 暫停後補發舊效果。死亡與 Runtime 更換清除／丟棄後座力。閃現通常不開移動後座力，仍維持前次確認。

## 套用步驟與起始範例

1. 退出 Play Mode，在 Project 開啟欲調整的 Runtime Prefab。
2. 選根物件的 Player Ability Runtime，展開 Recoil；每個技能獨立設定，沒有全技能批次套用。
3. 先勾 Camera Enabled，Camera Angles 可從 **(-2, 0)** 度開始，Camera Timing 勾選前搖前、前搖後，或兩者。
4. Camera Application Duration 可先用 **0.06 秒**，Recovery Delay **0.1 秒**、Recovery Speed **20 度／秒**。想柔和抬頭調施加時間；想延後／加快回落則調回正延遲／速度。
5. 勾 Movement Enabled，方向先保留 **(0,0,-1)**。Movement Speed 是初速，新增 Movement Decay Duration 是衰減時間；例如 **5 m/s、0.2 秒** 約提供 **0.5 公尺**額外位移。Movement Timing 仍可獨立複選。數字僅供手動試調，未套用資產。
6. 若想斜向後上，可試 **(0,0.4,-1)**；這個「上」是瞄準座標的上方，仍跟著俯仰旋轉。
7. 只保存該 Prefab 的調整，不需 Apply 玩家 Scene Instance，也不需重跑能力資產建立工具。
8. 重新進入遊戲並裝備該技能後測試。僅在 Play Mode 調整場上 Runtime 的值只供試驗，不會永久保存。

上述數字只是手動調整起點，本輪沒有套用到任何資產。一般有前搖 E 的前搖長度仍在同顆 Prefab 的能力模組 → 共用 E 技能設定 → Cast Delay Seconds；本次不改該值，也不為舊技能增加前搖。

Prefab 設定不是玩家存檔中的平衡參數；既有存檔還原 Ability ID 後，重新生成 Runtime 才讀取新配置。已生成實例不保證隨資產修改即時重讀。測試請重開 Play Mode，正式多人部署須所有端使用相同版本。

## 網路與驗收

成功觸發由 Host／State Authority 決定，Runtime 確認 Spawned、Owner 有效、存活與雙方 State Authority 後才寫入既有 KCC 視角／ExternalDelta。Client 不自行追加同一次後座力；沿用既有 KCC 同步／校正。PlayerAbilityRuntime 新增 Networked 待施加 Pitch／Yaw、剩餘施加時間、累積 Pitch、回正 Timer、交替序號及每 Tick 去重紀錄；由 State Authority 推進，Proxy 不按序號補播。沒有新 RPC、NetworkObject 或移動控制器。晚加入／重連接收當前狀態，尚在進行的效果隨 KCC 同步，已結束事件不重新觸發。

人工驗收順序：

1. 單人／Host 裝備技能，設前搖 0.5 秒，比較 Camera BeforeCast、Movement AfterCast；應先抬頭，出手時才後退。
2. 對調時機；前搖期間移動並旋轉 90 度，AfterCast 應使用新方向。看向地面時確認反向含向上分量。
3. 先只開一個通道，再全勾時機、最後全部關閉，確認前／後各一次與獨立控制；長按、冷卻、取消前搖不得額外觸發。連射時用技能並手動壓槍，確認自動回正不互相吞掉、也不把同一份下壓量扣兩次。
4. 地面、空中、貼牆、鉤索拉動、閃現待命與第二次衝刺、空中緩速解除各測一次，確認碰撞與原有移動優先權。
5. 獨立 Host＋Client 由 Client 按 E，確認本機視角、Host 觀察到的角色位移一致，無雙倍後座力；有延遲時檢查校正與手感。
6. 施放後再加入／重連，確認不補播舊的視角踢動或移動增量；換能力／死亡重生不殘留事件。

V3 聚焦 EditMode 23/23、受控 Single Runner 55 項及同 Editor 程序 Host／Client 22 項檢查通過；包含閃現第一次準備／第二次施放、阻擋／長按／逾時、投射施放失敗，以及 Input Authority、Proxy、晚加入與重連。完整回歸回報 562 項完成、1 項既有 Boss 資產引用失敗，result=null。獨立雙程序／雙機、實際手感與全部技能自然操作仍需上述人工驗收。詳見 [證據與重跑方式](Validation/AbilityRecoil/V3/README.md)。

## V4 位移驗證與試調

本輪原始量測（初速 10 m/s、觀察約 0.8 秒）：地面後座力約 0.345 m、空中約 3.914 m。改用 0.4 秒線性衰減後，額外距離約 2 m；途中落地與帶原速度亦一致。碰牆提前停止、不補發；向上後座力可離地。

閃現設定 8 m，在平地／空中均測得 8 m、結束無殘速；碰牆提前停止。因此本輪保留原閃現程式，沒有把未重現的現象直接歸因於摩擦。若實際關卡仍有差異，需記錄該處地形、起始速度與是否仍按方向鍵，以區分技能距離、碰撞及結束後普通移動。

驗收時先靜止、視線水平、無障礙，分別測地面／空中；再測途中落地、向上／向下、原速度、牆角、鉤索、空中緩速與子彈時間。距離一致指技能額外貢獻，並不取消重力或強制穿越地形。最新證據與重跑見 [AbilityMotion](Validation/AbilityMotion/README.md)。

- 2026-10-08 V4：新增 Movement Decay Duration 與有限時間位移，沿用原 KCC；保留人工資產，未改閃現演算法。
