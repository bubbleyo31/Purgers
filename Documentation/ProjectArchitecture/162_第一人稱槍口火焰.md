## 完成範圍

2026-09-25 後續：使用者回報功能沒問題，並要求依新的尖角黃白槍火參考重製為立體風格。已將同一路徑 `StylizedMuzzleFlash_4x3.png` 替換為立體切面火舌版本，維持 1448×1086 RGBA／4×3、原 GUID 與材質引用。舊圖備份於 [StylizedMuzzleFlash_v1.png](Validation/MuzzleFlash/StylizedMuzzleFlash_v1.png)。本次不更動播放程式、Prefab 或使用者調好的參數；下文未接線狀態是初次程式交付當時的紀錄。使用者功能驗收不等同另行完成獨立 Host／Client 自動驗證，新版美術仍待遊戲內觀看。

程式、4×3 透明圖集與 URP 材質已提供。Scene／既有 ViewModel Prefab **未自動掛載或接線**，請依下列順序手動配置。Editor 的獨立渲染見 [實際材質預覽](Validation/MuzzleFlash/EditorRender.png)；不是遊戲中的 Host／Client 開火截圖。

## 觸發與權責

`PlayerWeaponController → AttackRifle / SupportSMG` 沿用既有射擊、消耗彈藥、冷卻及命中流程。兩把槍在射擊條件成立後增加 `ShotSequence`，本次不改它們的 Gameplay。

`ProfessionViewModelManager → FirstPersonMuzzleFlash` 綁入當前職業的實際武器、Owner、Aim、Quick Action、既有 `WeaponViewModelReferences.MuzzlePoint` 與指定的 WeaponCamera。火焰在 LateUpdate 只讀成功射擊序號，不讀滑鼠鍵，也不透過 Animator 反推開槍。

- 只允許有效且具 Input Authority 的本地 Owner，以及該 Owner 當前職業對應的 AttackRifle／SupportSMG。Tank 不綁此元件。
- Client 沿用既有槍械的預測序號做本地呈現；這不是額外的 Host 確認 RPC。傷害、彈藥與世界結果仍由原權威流程決定。
- 綁定、恢復有效來源與重新啟用時只建立序號基準，不重播舊射擊。前進序號觸發，回捲／同序號不重播；支援 int 正負邊界。
- Runtime 重新綁定、換武器、職業不符、來源失效、ViewModel／元件停用、死亡、相機失效會移除圖形。換彈、Aim 階段、Quick Action 階段、Action Gate、Attack Focus 模式、Support 特殊模式變化也會清除舊尾焰。
- 彈藥消耗、射速冷卻倒數屬正常射擊過程，不是每幀銷毀理由。新射擊則從第 0 格重播。

## 效能與跟隨方式

每個已配置的本地 ViewModel 同時最多一個 `LocalMuzzleFlash` Quad。第一次實際開火才建立，接下來重用同一 Renderer、Mesh、MaterialPropertyBlock 與共享材質；沒有每發 Instantiate、Coroutine、Timer 佇列或貼圖複製。播完隱藏以便重用，武器狀態中斷則停用並 Destroy 自建物件與 Mesh。

高速連射會重新開始火焰，因此持續射擊時不保證看完整段煙霧。若一個畫面間隔包含多個模擬 Tick 的射擊，合併呈現最新一發，不補播積壓的射擊。這是固定容量的保險，並不限制槍械射速。

Quad 是 `MuzzlePoint` 的子物件，LateUpdate 順序 1100，在既有 Motion Controller（1000）之後更新槍口座標與面向。朝向使用 WeaponCamera 的旋轉，UV 使用當前格；不會把火焰留在發射當下的地圖座標。WorldCamera 必須排除 ViewModel Layer。

## 手動配置順序

1. 開啟 `Assets/Prefabs/ViewModel/手與槍械01.prefab`（Attack）。在已有 `WeaponViewModelReferences` 的 ViewModel 根物件加上 **FirstPersonMuzzleFlash**，整個 Prefab 只加一個。
2. 將 `Assets/Art/VFX/MuzzleFlash/MuzzleFlash.mat` 拖入 **Flash Material**。保留預設的 Screen Height、Frames Per Second、Image Pivot，儲存 Prefab。
3. 對 `Assets/Prefabs/ViewModel/手與槍械03.prefab`（Support）做相同步驟。兩個 Prefab 可分別調整尺寸與速度。
4. 檢查兩者既有 `WeaponViewModelReferences.MuzzlePoint`：本輪 Editor 讀取兩者均指向 `Muzzle`。確認它確實位於模型的槍口，會隨槍械動畫移動；不要改 Gameplay Shot Origin，也不要重建另一套槍口搜尋。
5. 在 `_Menu` 的 **ProfessionViewModelManager** 元件，將 **Muzzle Flash Camera** 指定為同一 CameraRig 的 `CameraEffectsRoot/WeaponCamera`。現有 `ViewModelRoot` 是 `CameraEffectsRoot` 的子物件，並不在 Camera 下，因此此處必須明確指定相機，不能假定父階層必然有 Camera。
6. 確認 WeaponCamera 渲染 ViewModel 圖層，WorldCamera 排除此圖層。本輪讀到 WeaponCamera mask=256、WorldCamera mask=759，ViewModel Layer=8。其他獨立啟動場景若有自己的 Manager，也需指定對應 WeaponCamera。
7. 儲存場景，再進 Play Mode。Manager 會從 ViewModel 找到新增元件並綁定來源；不需手動拖 Runtime 的 Rifle／SMG／Player，也不要加 NetworkObject 或 NetworkTransform。

缺少材質、槍口或相機時會安全不顯示。此版本不會自動修改 Prefab／Scene，也不會用 WorldCamera 偷代替 WeaponCamera。

## Inspector 調整說明

| 欄位／位置 | 預設 | 有效範圍與效果 | 建議驗證 |
| --- | --- | --- | --- |
| ViewModel → FirstPersonMuzzleFlash → Screen Height | 0.18 | 0.01～0.5；整格圖占 WeaponCamera 畫面高度比例，包含透明留白。0.18 是 18%，不是世界公尺 | 先試 0.12／0.18／0.24，比較腰射與 ADS 是否遮住準心 |
| Frames Per Second | 24 | 1～120 格／秒；總時長=12÷FPS，預設 0.5 秒 | 連射與放開後觀察收尾；36 為約 0.333 秒 |
| Image Pivot | (0.5, 0.38) | 兩軸 0～1，左下為原點。這張生成圖的爆發中心較低，因此不是 (0.5,0.5) | 停在爆發格確認亮核貼住 Muzzle；改圖集才通常需要重調 |
| Flash Material | 尚待手動指定 | 使用已提供的 MuzzleFlash.mat；貼圖布局固定 4×3、12 格，不能直接換成任意排列 | 不應粉紅、黑框或出現相鄰格 |
| Manager → Muzzle Flash Camera | 尚待手動指定 | 指定 WeaponCamera；空值不播放 | 旋轉視角、ADS 與武器晃動後仍貼槍口 |

尺寸用實際相機投影矩陣換算：透視時 `世界高度 = 2 × 槍口相機深度 ÷ |projection.m11| × Screen Height`。不修改 Camera FOV。槍口落到相機 near／far 裁切範圍之外則隱藏；不要靠極大尺寸掩蓋錯誤的槍口位置。骨架祖先應避免非均勻／負縮放，以免旋轉加縮放產生剪切。

圖集是 1448×1086 RGBA，每格 362×362；保留原始尺寸、不開 mipmap、Clamp／Bilinear、無壓縮、Read/Write 關閉。Shader 使用半像素內縮避免串格，透明混合、無燈光、無陰影、不寫深度。以共享材質引用保留 Shader 在 Build 的依賴。

Play Mode 調整 Runtime ViewModel 的欄位可立即看效果；離開 Play Mode 不會保存，需記錄數值再改 Prefab。Manager 的相機引用請在啟動前設定，變動後重新進場以重新綁定。設定不寫存檔，不同步到其他玩家，每台裝置只呈現自己的第一人稱火焰。

## Play Mode／多人驗收順序

1. Attack 與 Support 各單發：`ShotSequence` 前進才出現火焰；空彈、換彈中、冷卻中、Action Gate 阻擋時按左鍵不製造假火焰。Tank 左鍵攻擊沒有槍火。
2. 連射期間快速轉身、移動、ADS、武器晃動：火焰跟著 Muzzle，朝向 WeaponCamera，不留在世界原座標。兩把槍分別調整 Screen Height 驗收。
3. 火焰未播完就換彈、近戰、切職業、同職業 Runtime 刷新、切換特殊／Focus 模式：舊圖消失；新綁定不閃播歷史射擊。死亡、重生、切場、離線、元件停用也要驗證。
4. 高射速連射至少 30 秒：當前 Muzzle 子階層最多一個 `LocalMuzzleFlash`；停火後只保留一個隱藏物件；切職業後舊物件／Mesh 消失。Profiler 檢查穩態不逐發新增 Mesh／Material／GameObject，不能只拿 EditMode 迴圈當效能實測。
5. 使用獨立 Host 與 Client 各自執行 1～4，再測晚加入／斷線重連。自己的開火有火焰、別人的開火不驅動自己 ViewModel；新加入不重播歷史序號，無尚未 Spawn 的 Networked 存取錯誤。

自動測試與實際執行證據見 [驗證紀錄](Validation/MuzzleFlash/README.md)。以上遊戲內與獨立 Host／Client 驗收尚未執行。
