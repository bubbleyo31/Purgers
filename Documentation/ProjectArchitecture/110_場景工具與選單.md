## 維護原則

- Editor 程式維持在 `Assets/Scripts/Editor` 或 Editor-only Assembly，避免進 Build。
- Debug Gizmo 不可在 Runtime 每幀產生 GC 或更改 AI 狀態。
- 測試生成與測試移動物件不能被正式波次、任務或存檔系統依賴。
- `GameLogic` 若繼續擴張到回合、Encounter、計分與結算，應拆成各自 Controller，不要變成全域 God Object。

## 2026-09-17 局部核對與架構補充

MapGeneration/Prototype 的 MapChunk／MapConnector 提供區塊與接點資料。MapRunSelectionPrototype 在 Marker 模式使用固定 Seed 並支援 F9 重抽；Fusion 模式每個 Host Runner 產生一次新的 Run Seed，從四個入口隨機固定本輪出生點，再從其餘三個方向抽選出口。同一輪死亡重生沿用入口。ConnectorAlignmentPrototype 依 Run Seed 從 Host Chunk Prefab 候選池與四個入口方向抽選，生成並對齊唯一一個第二 Chunk；目前候選池只有 MapChunk_Prototype，因此現階段隨機差異主要是連接方向與旋轉。對齊成功後，MapConnectorBlockerPrototype 保留第一 Chunk 出口與第二 Chunk 入口形成的接合點，其餘六個 Connector 均生成阻擋屋，包含玩家出生入口。每個 Connector 可指定 Blocker Spawn Point 來校正建築 Prefab 的 Pivot 與朝向；留空時使用 Connector Transform。Blocker Local Position Offset 以錨點局部 X／Y／Z 調整實際生成位置，Scene 與 Prefab 編輯視窗會顯示偏移連線、生成點、朝向與可調尺寸的預覽框。MapChunk Prefab 保存 Editor 預先烘焙的 NavMeshSurface/NavMeshData；阻擋屋生成後，MapRuntimeNavigationPrototype 依兩個 Chunk 的位置與旋轉載入資料，在接合 Connector 建立雙向 NavMesh Link，未使用入口則由阻擋屋的 Carving NavMeshObstacle 封閉。接著系統依 Connector 邊界取樣並為每個 Chunk 建立最大可連通 Ground Patrol Area。地面敵人仍由 Fusion Tick Navigator 使用 NavMesh 查詢，不新增 NavMeshAgent。離線 Marker、F9、N 鍵入口遇任何 NetworkRunner 都不執行。Host 生成的第二 Chunk、阻擋屋與 Runtime Patrol Area 目前仍是普通 GameObject，不會同步到 Client，也不允許第三塊或循環生成。
