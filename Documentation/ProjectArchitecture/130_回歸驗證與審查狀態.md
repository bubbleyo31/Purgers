## 如何重跑

Unity 開啟 `Window > General > Test Runner`，切至 EditMode，執行全部測試或 `PurgersRegression` Category。MCP 可用 `run_tests` 指定 `mode: EditMode`，再以 `get_test_job` 取得結果。本輪完整結果 total 必須為 38；succeeded 但 total=0 不算通過。

測試檔位於 `Assets/Scripts/Editor/Tests`。MonoBehaviour 替身位於 `Assets/Scripts/Tool/Testing` 且包在 UNITY_EDITOR 條件內，因 Unity 不允許將 Editor 組件的 MonoBehaviour 掛到暫時 GameObject。測試結束會移除暫時物件，不修改 Prefab。

## 仍存在的架構工作與驗證邊界

1. **大型模組仍需逐步拆分。** Grapple、ViewModel Motion、TankAirDash 同時含多段狀態與表現；下一步先建立狀態轉移與多人回歸，再抽取純計算或表現責任。此次不搬動 Networked 欄位或重建 Prefab。
2. **自訂 Loadout 的跨死亡保存尚未實作。** GameLogic 保存職業，重生後套用 startingLoadout；正式選裝系統需先決定持久化規則。
3. **正式職業選擇流程尚未設計。** F1–F3 是開發功能。未來大廳／回合切換應有權威端遊戲階段驗證，不可直接取消測試入口限制。
4. **音效有 5 組相同內容。** 11 個檔案可節省約 93,888 bytes；保留各職業資產與 Cue 設定，待真正需要統一來源時再重映射。Photon 套件重複檔不自行清理。
5. **相容分支與 Test 命名不可直接當垃圾刪除。** TestDamageReceiver 是正式敵人生命來源；舊 fallback 欄位與 Loadout 快取要依使用情境與量測決定是否移除。
6. **尚未完成獨立 Host／Client、完整遊戲流程與效能驗證。** SafeHouse Host 單機已通過；仍需第二程序驗證加入／離線／兩端 Ready 與同步切場。其他待測包含 Q 按住與放開、充能／衰退與傷害一致性、換職業／死亡／重生 Runtime 清理、Tank 近戰與敵人 AI 導航，以及連線期間的地圖原型隔離。
7. **存檔 Menu 與 SafeHouse 進場已完成單機 Play Mode 驗證。** `_Menu` Continue UI 與 `_Menu → SafeHouse → Game` 已實測；連線失敗回滾、Unity 重啟後 Continue、獨立 Client 加入，以及 `Game → SafeHouse` 結果流程仍須實測。
