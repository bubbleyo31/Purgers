# 異常狀態圖示與持續量條

最後核對日期：2026-10-18（本功能局部核對）  
核對來源：`Assets/Scripts/UI/Status`、各狀態 Owner、`StatusEffectHudSetup`。  
相關文件：[100 UI](100_UI觀戰與聊天.md)、[101 隊友](101_隊友辨識與穿牆顯示.md)、[102 敵人血條](102_敵人百分比分格血條.md)、[驗證](Validation/StatusEffects/README.md)。

## 已確認規則

- 只顯示圖示與剩餘量條，不顯示文字、數字、百分比、秒數或層數。
- 不同異常依固定順位由上至下排列，全數顯示。同種異常只有一列。怪物／隊友整組異常列位於血條上方，最末列貼齊血條上緣加間距；消失後依實際可見列收合。
- 拉取、聚怪、擊退等短暫位移不顯示；Support 拉取前有明確期限的定身顯示。
- 怪物有可見異常時，即使滿血且未扣血也顯示原本血條。異常消失後回到原生命變化 10 秒窗，不另起 10 秒。Boss 排除；沿用既有遮擋、距離、顯示預算與大型怪物備用位置。
- 自己在準心下方置中顯示，原左下生命 HUD 回復原位置。隊友在頭頂血條上方顯示，名字在異常列上方；沿用穿牆規則，畫面外仍只有箭頭。
- 死亡、Despawn、來源失效或離房清空。觀戰沿用生命 HUD 已選定的目標，不另立玩家選擇器。
- 子彈時間對玩家也顯示；即使當次技能的玩家移動倍率是 1，仍是子彈時間狀態。

## 量條比例與網路責任

1. 首次生效以當次期限為分母，從滿格開始。延長最終期限時以新的剩餘時間重設分母；同種較短來源不重填。
2. 標記是明確刷新，即使刷新後較短仍重新滿格。最長來源被取消而總期限縮短時，保留原分母、立即縮短量條；所有來源消失就隱藏。
3. 既有 Owner 暫停狀態計時時，顯示讀相同 timer／progress；不使用 `Time.time`、HUD 自己累減或事件重播。
4. 各 Owner 新增同步顯示分母；子彈時間及減速以 `StatusEffectClock` 保存聚合期限與分母。這些欄位只供呈現，不裁定玩法。晚加入、重連、遮擋後重現按同步比例恢復。
5. `StatusEffectSnapshot` 是本機唯讀顯示資料；`StatusEffectSources` 快取各 Owner，所有 Networked 讀取都需通過各 Owner 的 Spawned／Object.IsValid 守衛。
6. State Authority 更新期限與分母；Input Authority、觀察者與本機 HUD 不改玩法。新增同步欄位後，Host／Client 必須使用同版程式與 Fusion weaving 結果。

## 圖示來源與設定

共用設定：`Assets/Resources/Presentation/StatusEffectHud.asset`。三個既有 HUD 讀同一份 Resources 設定，不必新增 NetworkBehaviour 或重新掛玩家／敵人呈現元件。

- `Assets/_Project_Assets/UI/StatusEffects/V1/BulletTime.png`：以原技能雙眼圖示去掉子彈、保留輪廓紋理的已確認紫色成品。量條也用紫色。原技能圖示資產未改寫。
- `GrappleBlocked.png`：以標準鈎索圖示加紅色禁止圓框與斜線的已確認成品。原鈎索技能圖示未改寫。
- `StatusSymbols.png`：依已確認完整預覽整理的透明 3×2 圖集，上排暈眩／定身／破綻，下排標記／捕食／減速。透過 Unity Sprite 矩形切分，不在 HUD 裁切或重畫圖示。

| 設定 | 初始值 | 作用 |
|---|---|---|
| World Icon Size／Bar Height／Row Gap | 16／4／3 | 怪物與隊友的 1080 高度參考像素；跟隨原頭頂 HUD 縮放 |
| Self Icon Size／Bar Height／Row Gap | 24／6／4 | 自己 HUD 的 Canvas 單位 |
| Self Width | 280 | 列寬，不超出 HUD 容器寬；置中對齊準心 |
| Self Crosshair Offset | 80 | 準心中心至自己第一列頂端距離；可在 Inspector 試調 |
| Health Gap／Icon Bar Gap | 5／5 | 頭頂血條上緣至最末列底端、圖示到量條的間距 |
| Styles | 8 項 | 各狀態的完整 Sprite 與量條顏色 |

`Tools > Purgers > UI > Create Approved Status Effect Assets` 只建立缺少的設定，不覆寫人工值。`Restore Health Position For Center Status HUD` 只在乾淨 `_Menu` 將先前為異常列預留的上移恢復：HealthBar anchoredPosition.y 從 -912.06366 回復 -967.7671，其他座標與生命／護盾樣式保留；若位置另有人工修改則拒絕覆蓋。StageHUD Prefab 沒有此常駐生命群組，因此不修改它。

自己狀態仍由 `LocalPlayerHealthSlider` 綁定生命／觀戰目標，但 UI 子物件改掛全畫面的 PlayerHUDController，使用其中心而非生命條位置；不跟隨準心 Graphic 的換色或開關。怪物上邊界為整組狀態預留高度；靠近畫面最上緣時，沿既有安全範圍限制可能將血條下推，大型怪物仍走原備用定位，這不是絕對避開模型的保證。隊友依名字與異常整組高度判定畫面內空間。

匯入解析度：雙眼與禁止鈎索上限 512；六格圖集上限 1024，保留來源 PNG、不產生 mipmap。三張 RGBA32 約 4.67 MiB 原始像素。

## 驗證界線

程式、圖示與 `_Menu` 空間配置已接入。聚焦、完整回歸、受控 Host／Client、離屏渲染及尚待自然實戰的證據分列於 [驗證紀錄](Validation/StatusEffects/README.md)。人工調整圖示大小或準心偏移後需重新檢查四列與中央換彈／救援 UI 的同時顯示空間；相機分割視口、超寬螢幕與大量怪物負載仍應以實際場景驗收。
