# HUD 按鍵提示共用美術與位置

最後核對日期：2026-10-21（局部核對：ALT 獎勵提示與專注技能丟棄提示）。

核對來源：HudKeyPromptStyle、HudKeyPromptLayout、HudKeyPromptRow、各 HUD owner、HudKeyPromptStyleSetup、正式 Scene／Prefab。

相關文件：[104 玩家設定](104_ESC選單與玩家設定.md)、[167 已確認 HUD](167_已確認HUD美術與整格血量.md)、[100 UI 責任](100_UI觀戰與聊天.md)。

## 定案與責任

使用者授權修正 Energy 的 Q 背景／文字偏差，盤點所有遊戲內提示並集中美術入口。能量、能力、換彈、救援、準備、觀戰、獎勵與互動鍵帽共用同一份 Sprite、字體、字形置中、內距與狀態色。使用既有核准 SkillSquare 美術，未生成或重畫替代圖。

- 唯一美術資產：`Assets/Resources/Presentation/HudKeyPromptStyle.asset`。
- `HudKeyPromptLayout` 沿用既有排版責任，增加共用樣式及依 owner 提供的 pressed／unavailable 套色；不自行讀取輸入、不決定可用資格。
- `HudKeyPromptRow` 將原提示文字框呈現成「鍵帽＋說明」，或透過 `RefreshWithPrefix` 呈現「Description1＋鍵帽＋Description2」，保留外層錨點與座標；在窄列等比縮小，不把長鍵名截掉。
- 原 HUD owner 繼續讀取原 InputManager／PlayerSettingsService、顯示資格與生命週期。沒有新增輸入、存檔、冷卻或權威系統。
- 可改鍵提示讀目前綁定；設定頁範例讀尚未儲存的 Draft。固定 ESC、觀戰 Q／E、獎勵滑鼠左／中／右仍按原功能規則，不借用戰鬥 Q／E 改鍵。
- 技能掉落「拾取／替換」已移除寫死的 [E]，使用 Interact 共用綁定。救援狀態文字在有鍵帽時不再重複印出另一顆裸字 E。
- 新增按鍵提示必須接此美術資產，並同步本表、資產清單及 PLAYER-SETTINGS；純敘述文字／一般選單按鈕不屬於鍵帽。

## 共用 Inspector 設定

在 Project 選取上述 HudKeyPromptStyle.asset 即可調整；不是修改個人設定 JSON。

| 欄位 | 本次基準 | 用途 |
|---|---|---|
| background | ApprovedV2/SkillSquare.png | 全部鍵帽背景 |
| imageType／backgroundMaterial | Simple／預設 UI 材質 | 可換成已設定 border 的 Sliced Sprite；需重新檢查伸縮 |
| font／fontMaterial | NotoSansTC-Bold HUD SDF | 全部鍵帽字型與材質 |
| fontStyle／textColor | Normal／黑色 | 不額外套一份粗體或縮放 |
| readyColor | #F1EDD9 | 米白底 |
| pressedColor | #D5C45E | 按住的淡金底 |
| unavailableColor | #6F7363 | 不可用或未配置 |
| height／minimumWidth／maximumWidth | 32／32／104 | Canvas 基準單位；字寬＋左右內距，限制最大寬 |
| padding | (8, 2) | 左右 8、上下 2 |
| fontSize／minimumFontSize | 21／10 | 長鍵名在寬度上限內縮字，單行、不省略 |
| textOffset | (0, 0) | 全體光學微調；不另設 Energy／Q／E 偏移 |
| belowGap | 19 | 能量環／能力槽底緣到鍵帽頂緣 |
| inlineGap | 8 | 鍵帽與同列說明文字間隔 |

文字使用 TMP `MidlineGeoAligned`（可見字形幾何對齊），統一字重、間距、縮放與旋轉。uGUI 明確設為 orthographic，避免尚未啟用的 TMP 以 3D 的 0.1 倍尺寸量字。能量環／技能槽使用父／兄弟物件的本地座標計算間隔，Prefab Canvas 尚未啟動、根物件縮放為零時也不會算出錯位。

## 日後統一換美術

1. 修改 `HudKeyPromptStyle.asset` 的 background、font／fontMaterial、色彩、內距或尺寸，儲存該資產。換字型時同步指定其匹配材質。
2. 新建立的所有提示會讀取同一個 Resources 資產；顯示中的 owner 在下一次 Refresh 會讀取 Inspector OnValidate 的樣式版本。隱藏 HUD 在恢復顯示時更新。
3. 如需把非播放時的 Scene／Prefab 外觀及清單一併同步，先儲存自己的場景修改，再執行 `Purgers → UI → Apply Shared Keycap Style`。工具只處理上表登錄的鍵帽及行內提示，不重跑 BattleHudReferenceLayout 全版套版；目標場景有未儲存內容時拒絕開始，避免夾帶別的工作。
4. 工具更新 StageHUD、PlayerRescueHUD、SpectatorHUD、_Menu、SafeHouse，重新匯出 PromptInventory.json。共用美術資產本身不會被工具重設成預設值。
5. 使用 `HudKeyPromptPreview.Render` 檢查 Energy／技能對齊，`RenderCatalog` 檢查長鍵名、滑鼠、按下／未配置；兩者皆為 Preview Scene 離屏渲染，不聚焦 Unity。
6. 新圖的透明留白、邊框厚度與字型光學比例仍需視覺檢查；調整共用 textOffset／padding，避免在每個 HUD 各自補偏移。

## 實作與驗證狀態

共用資產、Runtime 接入及上列 Scene／Prefab 已實際套用。更換 Sprite／字型不需要逐一修改各提示的程式。圖片是 Unity 原生 UI 離屏結果，並非網頁模擬。

2026-10-21 ALT 提示已依確認預覽套用。丟棄提示的 `focusManagementHintOffset`／`focusManagementHintColor` 位於 LocalPlayerBattleAbilityHUD 的「ALT 技能管理」；整列 CanvasGroup 沿原權重淡出，鍵帽本身保留共用樣式。此次測試、資產核對與完整回歸未完成的限制見 [ALT 提示驗證](Validation/FocusPromptLayout/README.md)。

聚焦測試、完整回歸、資產核對、離屏圖片與自然操作待驗界線見 [本次驗證](Validation/HudKeycaps/README.md#2026-10-19-共用美術與全提示盤點)。視覺一致性仍待使用者在實際遊戲畫面確認；未以離屏預覽宣稱獨立 Host／Client、Build 或自然救援／拾取流程通過。
