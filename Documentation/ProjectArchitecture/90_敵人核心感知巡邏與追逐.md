## 分層狀態

Enemy 同時有三種不同維度，不應壓成單一 Animator enum：

- `EnemyBrainState`：Idle、Patrol、Alert、Chase 等思考狀態。
- `EnemyActionState`：當前攻擊／防禦／受控等動作。
- `EnemyControlState`：一般 AI、外部鈎索控制、死亡等控制權。

`EnemyStateController` 保存這些狀態；`EnemyActionGate` 與 `EnemyMovementOwnership` 分別仲裁動作和位移。

## 感知與群體警報

```text
EnemyPerceptionController
→ 找到視野／距離內玩家
→ EnemyAwarenessBrain
   ├─ Detection 表現階段
   ├─ 已鎖定記憶範圍
   └─ EnemyAlertDirector 群體呼喚
→ Chase Brain
```

| 程式 | 職責 |
|---|---|
| `EnemyPerceptionController.cs` | 視野、距離、遮擋與存活玩家掃描；管理親眼鎖定後的有限即時位置保留與可攻擊視線 |
| `EnemyAwarenessBrain.cs` | 發現、Alert 與受傷警覺；依 Perception 的有限目標保留切換 Chase／Investigate，不自行決定保留期限 |
| `EnemyAlertDirector.cs` | 控制小區域群體呼喚與冷卻，避免所有 Enemy 同時進 Detection 動畫／音效 |
| `EnemyAwarenessAnimatorDriver.cs` | 將 Awareness Phase 轉成 Animator 參數，不參與感知判定 |

## Idle 與 Patrol

```text
EnemyIdlePatrolBrain
→ Idle 隨機左右／180 度觀察
→ 決定 Patrol
→ EnemyPatrolArea 人工節點
→ EnemyPatrolNavigator
   ├─ EnemyGroundPatrolNavigator
   └─ EnemyFlyingPatrolNavigator
→ 抵達後回 Idle
```

| 程式 | 職責 |
|---|---|
| `EnemyPatrolArea.cs` | 由 Patrol Points Parent 的直接子物件建立人工或 Runtime 規劃節點快取；提供節點查詢與詳細拒絕原因 |
| `EnemyIdlePatrolBrain.cs` | Idle 計時、轉向、巡邏決策、出生前 Area 綁定、同 ID 最近區域備援、節點候選與 Navigator 結果處理 |
| `EnemyPatrolNavigator.cs` | 地面／飛行 Navigator 共用抽象契約、Move Result 與 Plan Failure |
| `EnemyGroundPatrolNavigator.cs` | NavMesh 路徑規劃、移動、抵達與 Ground Gizmos |
| `EnemyFlyingPatrolNavigator.cs` | 飛行方向、障礙探測、抵達與碰撞 Gizmos |

巡邏只使用手工或 Runtime 規劃完成的節點，不在大球體中任取一點。巡邏是低優先行為，一旦 Alert、Chase、Combat、受控或死亡，就必須釋放 Movement Ownership。

## 追逐

```text
EnemyChaseBrain
→ 讀取 Perception 目標與 EnemyDefinition.ChaseKind
→ EnemyChaseMotor
   ├─ EnemyGroundChaseMotor
   └─ EnemyFlyingChaseMotor
```

| 程式 | 職責 |
|---|---|
| `EnemyChaseBrain.cs` | 追逐狀態、目標更新、攻擊後重整與 Chase Motor 選擇 |
| `EnemyChaseMotor.cs` | 追逐共用基底、Movement Ownership、目標與速度介面 |
| `EnemyGroundChaseMotor.cs` | 地面 NavMesh 追逐 |
| `EnemyFlyingChaseMotor.cs` | 飛行接近／後退／保持距離、障礙探測與 Gizmos |

MapChunk Prefab 保存 Editor 預先烘焙的 `NavMeshSurface/NavMeshData`。Runtime 地圖完成多個 Chunk 對齊與阻擋屋生成後，`MapRuntimeNavigationPrototype` 依各 Chunk 的位置與旋轉重新載入 NavMeshData，並在接合 Connector 內側建立雙向 NavMesh Link；未使用入口的阻擋屋以 Carving `NavMeshObstacle` 封閉。規劃器再依四向 Connector 推導取樣邊界，將候選點投影到 NavMesh、移除過近點，並保留最大可連通集合建立 `EnemyPatrolArea`。`Game.unity` 不應再掛載與各 Chunk 資料重疊的舊整場景 NavMesh；地面巡邏與追逐仍由 Fusion Tick Motor 推進，Enemy Root 不可啟用 `NavMeshAgent`，避免兩套系統同時寫入位置。

近戰 B Dash 結束後由專用重整行為重新面向並回到合理追逐，不應直接沿 Dash 殘留方向漫無目的移動。

## 動畫移速

Enemy 巡邏結束回 Idle 時，Animator MoveSpeed 以平滑下降而非立刻歸零。動畫速度使用基準比例：

```text
Animator Walk Speed Multiplier = 實際移動速度 ÷ Walk 動畫的基準移速
```

例如 Walk Clip 速度 1 對應世界移速 2；Enemy 實際移速改為 6 時，Walk 動畫倍率為 3。

## 2026-10-02 離開視野後的有限鎖定保留

局部核對來源：`EnemyPerceptionController.cs`、`EnemyCombatCore.cs`、`EnemyRangedProjectileAttack.cs`、`EnemyRangedBeamAttack.cs`、`EnemyCombatDecisionController.cs`。本節取代舊版「只要留在半徑內就無限追蹤」規則，適用所有使用此 Perception 的敵人，包含 Ranged C。

1. 初次發現仍必須通過正常距離、水平／垂直扇形與遮擋檢查。
2. 最後一次在正常視野內親眼看見時，State Authority 重設 `LockedTargetRetentionTimer`。此計時器與一般快照記憶 `TargetMemoryTimer` 分開。
3. 暫時離開扇形或被牆遮擋時，在期限與保留半徑內持續更新玩家即時位置；`HasDirectSight` 仍為 false。保留期間不因讀取位置或同伴情報自行續期。
4. 無遮擋的保留目標可經 `HasCombatSight` 啟動攻擊，投射物 Startup 與光束 Tracking 也使用此判定；牆壁遮擋仍阻止需要視線的攻擊。已鎖定的光束世界瞄準點與命中遮擋規則不變。
5. 無正常直接視線時，超時或超出保留半徑即清除 CurrentTarget，保留最後位置並交回原有 Investigate。若重新進入正常視野則重新確認並重設期限。死亡／離線仍立即排除。
6. 只有同伴快照、尚未親眼確認的玩家仍使用一般記憶；Combat Context 也只讀該快照，不繞過感知去讀即時 Transform。

`HasRetainedLineOfSight` 與計時器是新增 Networked 狀態；`HasCombatSight` 是有 Spawn 防護的衍生屬性。所有寫入仍由 Host／State Authority 處理；Client 只讀同步結果。視線／重新發現以原 Scan Interval 掃描，半徑與到期檢查每個模擬 Tick 執行；掃描間隔內仍可能存在上一輪視線快照。

### Inspector 調整與驗收

在敵人 Prefab Root 的 **Enemy Perception Controller → 掃描與記憶** 調整，重生敵人後測試；不要在 EnemyDefinition 或生成區尋找這些欄位。

| 欄位 | 預設／目前 C 值 | 合法範圍與效果 |
|---|---|---|
| Enable Locked Target Retention | true | 開啟有限即時位置保留；關閉則沿用一般舊位置記憶，不提供扇形外攻擊視線 |
| Locked Target Retention Seconds | 3 秒／3 秒 | 至少 0.02；越長越能容忍高速繞背，越短越容易甩開。只有正常親眼觀測重設 |
| Locked Target Retention Radius | 程式預設 25 公尺／C 既有 60 公尺 | 至少 0.1；觀測點到 Enemy Root 的三維距離。超出後不再享有視野外保留；不改正常 Sight Distance |
| Target Memory Seconds | 3 秒 | 至少 0.02；同伴快照與未啟用保留時的一般記憶，不會延長上面的親眼鎖定期限 |
| Scan Interval Seconds | 0.1 秒 | 至少 0.02；較短可減少視線狀態延遲，但增加掃描負擔 |

先讓敵人正常發現，再快速繞到側後方：期限內應繼續追蹤，且無牆時允許攻擊。若敵人轉身重新看見，期限重設是預期；驗證超時需持續留在視野外或遮擋後。接著分別驗證保留期間加入牆壁會阻止攻擊、離開 60 公尺的 C 保留半徑會解除鎖定，以及重新進入正常視野會重新取得目標。保留期間的牆後位置資訊是本規則的一部分，不代表允許隔牆傷害。

SpawnRootOffset=max(0,-BodyBaseOffset) 向上補償飛行出生 Root，與巡邏出生種子使用同一值。模型、骨架及原動畫不位移、不替換。受擊分段與粗略搜尋球獨立於通行包絡，不能將攻擊最大伸展直接當作移動半徑。完整設定、成本及證據見[水母校準](Validation/JellyfishCollision/README.md)。
