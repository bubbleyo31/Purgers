出生點前方街區局部渲染優化測試
日期：2026-10-20（Asia/Taipei）

結論
已完成限定 8 棟房子的前後對照，沒有擴大套用整張 Map。
畫面差異很小，原碰撞體與室內幾何保留。
繪製呼叫確實減少，但整個鏡頭的耗時收益有限且有波動，不能宣稱已解決
城市方向掉幀或已證明實際遊玩 FPS 提升。測試後全部還原，未儲存正式場景。

範圍
Game / Map(Z:-263) / MapChunk_Prototype：
場景模型v1：
  下出生點_左排_房子2、房子2-1-3、房子3、房子4
  下出生點_右排_房子2、房子3、房子4
額外自建：
  最靠近北入口的「煙囪三層房 (1)」
共 424 個啟用 MeshRenderer，佔目前 Map 8,558 個 Renderer 約 5%。
同名、位於其他區域的房子未納入。精確原物件路徑與 instance ID 見 scope.json。
正式 Collider、Transform、GameObject 啟用狀態、原 MeshFilter 與材質沒有改動。
僅在 Play Mode 暫時停用指定原 Renderer，改由暫存渲染物件繪製。

候選與結果
表中的 CPU 為 Inl_UniversalRenderTotal 經過時間，包含提交與等待；
GPU 為每輪相機 GPU 中位數再取三輪平均。不是 CPU 使用率，不能相加。
每個方案各自與同一輪的原版比較，不能跨輪把不同原版時間當作同一基線。

1. Unity 靜態批次（不保留為推薦方案）
   424 個來源的暫存副本全部進入靜態批次。
   整個鏡頭繪製呼叫：16,053 -> 15,332，約減少 4.5%。
   CPU 渲染：9.13 -> 9.49 ms，未改善。
   畫面差異小，但不能只憑 draw calls 降低就稱為效能成功。

2. 每棟同材質合併（較少繪製呼叫的候選）
   424 -> 8 個 Renderer，保留全部三角面。
   整個鏡頭繪製呼叫：16,046 -> 15,238，約減少 5.0%。
   CPU 渲染：10.59 -> 10.27 ms，平均約降低 3.0%。
   GPU：10.37 -> 10.07 ms，僅為本輪觀測值。
   CPU 原版三輪約 9.91 / 11.27 / 10.60 ms；
   候選三輪約 10.22 / 10.63 / 9.97 ms。
   波動範圍重疊，第一對並未改善，不宣稱穩定 FPS 收益。
   因合併後剔除粒度較粗，整個畫面實際繪製三角面（含多 Pass）
   約 1,425,471 -> 1,453,336，增加約 2.0%。
   新合併渲染 Mesh 約 2,288,784 bytes（2.18 MiB），原 Mesh 仍供碰撞使用。
   測試的可讀工作副本加上合併 Mesh 共約 5,062,416 bytes，已清理。

3. 每棟內的小空間群組（較細剔除的候選）
   以來源 bounds 中心落入的 X/Z 12 m、Y 8 m 格子分組，且不跨棟合併。
   這是分組單位，不代表每組 bounds 必定小於格子尺寸。
   424 -> 110 個 Renderer。
   整個鏡頭繪製呼叫：16,053 -> 15,461，約減少 3.7%。
   CPU 渲染：9.13 -> 9.34 ms，沒有穩定改善；保留第三輪較慢結果。
   GPU：9.26 -> 8.80 ms，但 CPU 與整幀未一致改善。
   實際繪製三角面約 1,426,058 -> 1,430,209，增加約 0.29%。
   新合併渲染 Mesh 約 2,452,800 bytes（2.34 MiB）。
   剔除粒度較保守，但現有數據不支持直接稱為較快方案。

獨立量測這段街區（不是整張 Map 的 FPS 結果）
另外只量方案 2 的 8 棟房子：暫時以 forceRenderingOff 隱藏其他 Renderer，
所有碰撞仍保留，量完逐一還原。這個診斷隔離沒有保存或當作正式優化。
繪製呼叫約 841 -> 30，CPU 渲染 1.64 -> 1.25 ms（約降低 24%）。
GPU 約 2.26 -> 2.28 ms，沒有改善。
這證明局部提交成本可降低，但無法把 24% 套用到整張城市或整場遊戲。
此時實際繪製三角面約 65,776 -> 93,595，也證明整棟合併的剔除代價。

畫面與幾何驗證
四個固定視角：出生點、道路前進、左側近景、右側近景。
每個視角皆有原版與候選 PNG，解析度 1920x1080，未補光、未調色。
未調低材質、SSAO、陰影或模型細節。
另拍原版連續兩張作噪聲基準，四個視角皆為逐像素相同。
兩個合併候選的畫面差異相同：
  出生點：平均每色彩通道差 0.000417 / 255；
          約 0.0909% 像素有任何差異，差值大於 3 的像素約 0.000579%。
  道路前進：逐像素相同。
  左側近景：最大通道差 1 / 255。
  右側近景：最大通道差 6 / 255，差值大於 3 的像素約 0.001013%。
不是宣稱所有位置完全像素一致；已檢視出生點與右側近景，未見明顯外觀變化。

合併前後來源幾何均為 30,680 個三角形，頂點數保留。
補驗了合併索引是否等於原三角形索引加對應頂點偏移，通過；
因此沒有以外殼、Convex、包圍盒或刪面替代原室內幾何。
世界座標頂點最大浮點誤差 0.0000305176 Unity 單位。
此範圍沒有 LightProbe、ReflectionProbe、Renderer property block、
lightmap 或負行列式來源變換；其他有這些設定的區域不能直接套用本例。

量測條件與限制
背景 PlayUnfocused，未搶焦點、未操作桌面鍵鼠。
每方案 3 輪原版與 3 輪候選；每段暖機 3 秒、取樣至少 5 秒。
原版/候選/原版/候選/候選/原版順序，用來暴露時間漂移。
無玩家、無網路 Session、無戰鬥；原世界相機設定複製到離屏相機。
HUD 與武器疊加相機不參與。Scene View 場景幾何在取樣期間暫時遮罩排除。
繪製計數包含仍存在的其他 Game 場景內容與少量 Editor 成本。
這是受控 Editor 渲染測試，不是正式 Player FPS 或自然遊玩驗收。

本輪可觀測的 Play Mode URP 設定：
renderScale=1、pipeline MSAA=1、陰影距離=50、1 級聯、1024 陰影貼圖，
SSAO 與 TeammateOutline 啟用。診斷 RenderTexture 是 1920x1080、
ARGBHalf、antiAliasing=4。本輪未寫入上述 URP 畫質欄位。
退出 Play 後 Editor 回到 URP-HighFidelity 的 MSAA=4、陰影距離=150、
4 級聯、4096 陰影貼圖，且資產不 dirty。
這與前一次全 Map 診斷的播放畫質不同，因此不得把兩次的絕對耗時或
draw-call 基線差距算作本輪優化成果。只使用本輪各方案的配對比較。

沒有新增正式功能或修改遊戲程式，故未執行全套 PurgersRegression。
結束時 Console 查無 error/warning。
自然室內走動、鉤爪、射擊、多人 Host/Client、Build 與其他視角尚未驗收；
本輪碰撞保障來自未修改碰撞資料及前後指紋核對，不冒充自然遊玩通過。
